# 产品可靠性与运维

本文描述 2.4.3 的产品可靠性与运维契约，发行二进制资格见[当前验证范围](validation-v2.4.3.md)。单机 direct/WAL、单组 Raft 和租户分片均保留；历史设计沿革见[设计说明](product-hardening-design.zh-CN.md)与[当时验证记录](product-hardening-validation-2026-10-02.zh-CN.md)。

## 磁盘保护

默认 `GRAPHDB_DISK_MIN_FREE_BYTES=256MiB`、`GRAPHDB_DISK_MIN_FREE_PERCENT=5`，取两者中更大的保留空间。检查当前文件系统的可用空间；独立 WAL 和 Raft 快照目录分别检查所在磁盘。

**2.4.3**同时检查 inode：`GRAPHDB_DISK_MIN_FREE_INODES=1024`、`GRAPHDB_DISK_MIN_FREE_INODES_PERCENT=5`，取两者中的较大值。字节与 inode 条件必须同时满足，inode 不足返回 `429` / `disk_inodes_low`。文件系统不提供有限 inode 总量时，诊断标记 `inodes_known=false`，不把未知值当作耗尽。数据、独立 WAL 和 Raft 目录使用同一配置分别检查；已受理 WAL 的数据发布可使用部分准入预留，但仍保留最多 64 个 inode 的最低余量。该检查不是并发资源预留，不能保证突然耗尽时每个已受理批次都能立即完成。

新写入低于阈值返回 `429`，原因 `disk_space_low`。压缩、索引重建、恢复和迁移准备阶段检查临时空间。已受理的 WAL 可以使用部分准入预留完成发布；读取、GC 和本地诊断仍可运行。维护任务因空间不足保留排队状态，轮询跳过受阻任务并在各租户间轮转，其他租户的 GC 可以继续执行；腾出空间后再尝试受阻任务。

估算不是并发空间预留，也不能替代 OS 配额和容量监控。已提交日志在副本上不能因本地空闲空间不同而产生不同业务结果；副本实际发生 I/O 错误时停止应用，需要修复该副本。不要删除 Raft 日志、WAL 或当前图文件来腾空间。优先清理已确认不再使用的外部归档，按正常 API 执行 GC，或扩展磁盘。

此修复在单机本地文件删除及 GC 的持久化屏障完成后回收空父目录，并通过目录 IO 锁避开并发创建、原子写入和目录替换。进入独占 IO 屏障前只读取父目录的一个条目，已有文件时跳过清理，避免普通控制文件删除等待其他租户的读写；真正删除目录时仍在屏障内重新确认。启动取得数据目录独占锁后，分批扫描并清理旧版残留的空目录和未完成原子写入的 `.tmp-*` 文件，保留正式 `.parquet` 对象、根锁、恢复和快照内部命名空间，不跟随符号链接。大量历史文件会延长启动扫描时间。历史批次与幂等记录继续保留原有重试语义，仍需纳入 inode 容量规划；本次不自动删除或迁移这些记录。

此修复默认启用单机管理元数据在线自愈，不需要配置租户名单或重启。正常访问发现 `metadata.parquet` 缺失或校验失败时，优先采用有效的未完成写入记录，其次采用有效主文件，再采用 `control/tenant-metadata-backup.parquet` 恢复副本；有可信副本时保留原状态及名称、标签等字段。没有有效副本时，只有有效且属于该租户的 manifest 存在、purge 标记缺失或已 `cleared`，才按 legacy 兼容语义重建为 active。此默认值不能证明历史状态；原始字段和创建时间不可推导，新记录以恢复时间为创建时间。`running`、`complete`、未知或损坏的 purge 标记阻止恢复。manifest 缺失或损坏时不会凭空创建新图。

首次直接写入、批量摄取和 `init-tenant` 在发布初始 manifest 前持久化管理元数据；新租户默认为 active，已有 disabled/deleted 状态仍阻止写入。元数据写入失败则初始化返回错误，不发布缺少管理状态的 manifest；本地重试可续写初始化留下的 pending。直接提交与批量摄取都先持久化空图 head，再暂存提交文件，避免首次发布失败后的残留文件被误判为已发布图丢失 manifest。仅初始 head 缺失时执行这一步，已有租户的正常提交不会逐次重写管理元数据。Raft 的初始化元数据属于复制写入，读取自愈仍限于单机。

读取使用可验证的恢复结果，同时由单个后台工作协程补登记并修复持久文件；队列最多容纳 64 个等待租户，同一租户合并重复请求，空闲后退出。修复重新取得租户锁并检查 purge、manifest、磁盘余量和当前元数据，避免覆盖同时发生的禁用、删除或替换。元数据锁等待遵循请求取消和超时，后台每次修复的五秒期限也包含等待锁的时间；不会因正在替换租户目录而无限排队。失败或队列满时由后续访问重新触发。普通 PUT 可直接完成相同的恢复后更新，无需先调用 enable。过程只访问固定的控制文件，不遍历、链接或替换整棵图目录；日志使用 `tenant_metadata_recovered`（source 为 pending/primary/backup/manifest）和 `tenant_metadata_recovery_failed`。

元数据写入先持久化 `control/tenant-metadata-pending.parquet`，再原子写主文件、同步恢复副本，最后删除 pending。中途失败后的读取与恢复采用 pending，防止把旧 active 副本恢复到刚禁用的租户。稳定状态每租户增加一个副本文件，更新时临时增加一个 pending 文件，不累积历史版本；健康旧记录在访问时自动补副本。此机制针对单机本地存储，Raft 读取不执行本地修复写入；Raft 中普通 PUT 仍对缺失管理状态返回 `409 repair_required`，须走集群生命周期操作。升级后新增的控制文件不改变图/WAL 格式；有 pending 时应先由修复版完成恢复，不能直接降级忽略未完成写入。

健康主文件已通过校验时，读取只比较副本字节，不重复解码相同内容；有效 pending 优先时不读取无须使用的旧副本。主文件损坏时仍完整校验恢复副本。若只是副本缺失、损坏或落后，且不存在有效 pending，后台在元数据锁内仅修复副本并清理无效 pending，保留主文件及其 inode，不另建写入意图；中断后可从未改变的主文件重试。实际状态更新或主文件恢复仍使用完整的 pending 发布流程。

恢复读取会将磁盘上实际存在性和摘要与条件写缓存核对，仅清除不一致项；磁盘损坏或外部删除未经过存储接口通知时，也不会因旧摘要反复产生写入冲突。正常摘要缓存继续保留，修复写入仍执行条件校验。


对于 `ENOSPC` 后持续出现 `prepared ingest result changed` 的单机，先停止新写入，保留 WAL、PREPARED 与 manifest，并在其他磁盘保存完整离线备份。修复版可重放 2.4.2 已持久化的字段别名冲突结果，不要求重写 WAL；提交身份、版本、图摘要和其他结果校验继续生效。恢复资源后启动，确认 WAL pending 清零、readiness 恢复和重复批次返回原结果，再恢复流量。其他无法证明一致性的 PREPARED 错误仍停止写入，不能删除日志或跳过校验强行恢复。inode 为零时 GC 自身也可能无法创建必要文件，应先恢复余量；如果启动清理释放不足，应迁移到有足够 inode 的磁盘。

## 快照和维护

2.4.3：已有 manifest、缺少管理元数据且未附带配置/来源策略模板的创建请求，只原子发布管理元数据，保持图目录、历史文件和幂等记录原位，不遍历或硬链接整棵图目录。包含模板、克隆或图替换的流程继续使用带恢复日志的目录发布。已完成发布或放弃构建的暂存目录交给单个后台清理工作协程，创建/恢复请求和租户锁不再等待递归删除；队列满时保留垃圾供下次启动回收，未完成的恢复日志始终保留。关闭文件存储会等待清理工作退出后再释放目录锁。

同步压缩和后台压缩任务在取得租户发布锁前扫描、结算历史直接提交的幂等记录，慢扫描不再持有前台写锁。无法证明结果的记录仍阻止压缩；发布时继续校验当前图来自已捕获的提交历史，保留扫描期间产生的新提交，不以缩短等待或忽略错误换取可用性。

[2.2.4 的复制完整性保护](product-p0-p1-review4-2026-10-03.zh-CN.md)覆盖已确认迁移分块在副本上的丢失/变化，以及 Raft 状态快照包含损坏的已发布图。故障副本不能消费安装日志；解码快照未验证通过时不能替换健康数据或推进应用位置。升级期间暂停迁移，先完成或在切换前取消旧迁移，目标全组升级后重新发起；旧程序留下的 importing 分块没有摘要绑定，不能直接推进切换。运维处置和兼容边界见[Raft 运维](raft-operations.zh-CN.md)。

当前实现同时绑定 Raft 数据目录、新命令与快照的 `GRAPHDB_PREFIX`。保持全组一致并沿用原值；配置错误时恢复原前缀后重启，不能删除身份标记。旧日志仍可读取，旧二进制不具备新增保护。

[2.2.4 的迁移修复](product-p0-p1-review3-2026-10-03.zh-CN.md)让离线 `tools/tenantmigrate -overwrite` 先完整复制到临时目录，冷加载验证图、当前摘要及关系 schema 后，再通过目录恢复日志替换目标租户。读取或校验失败保留原目标图；进程在目录切换中中断时，重开目录先恢复日志。工具只复制已发布的租户对象，不复制单机外部 WAL 目录；必须先排空已受理 WAL 和维护任务，再停止源、目标进程并取得目录独占锁，不能用它搬迁尚未恢复或排空的接入日志。工具拒绝对 Raft 副本目录直接操作。`-dry-run` 只清点文件和字节，不证明可恢复性或图完整性。暂存需要额外完整租户空间；公开复制函数的非本地对象存储分支只保证源端复制和校验失败发生在覆盖前，不提供目标 IO 失败时的原子替换契约。

2.4.3 要求迁移输入包含可校验、租户身份一致的 `metadata.parquet`。文件缺失、复制清单漏项或文件损坏都不能以成功覆盖结束；暂存校验在替换前拒绝输入，保留目标原来的图和管理状态。分片迁移的源导出及目标安装共用此检查。校验只读，不把缺失状态猜成 active；旧单机租户可先通过正常访问触发在线自愈，待管理记录落盘后再迁移。非本地目标写入途中发生 IO 故障时仍不提供整体回滚。

迁移冷校验先检查 manifest 和管理记录、配置等控制文件，再加载整张图；缺失或损坏的管理状态会在图数据读取与解码前被拒绝。离线复制仍需先生成暂存副本，因此这项检查顺序优化不消除复制暂存本身的 IO。

分片迁移同时校验源导出和目标解码文件；损坏输入不会改变目标代次或推进目录切换。失败时保留源数据，检查 `move.error`，按已有副本恢复流程处理源故障；取消迁移仍遵循目录切换前的限制。不要通过改摘要、删除文件或直接复制到正式目录绕过校验。

[2.2.4 的完整性修复](product-p0-p1-review2-2026-10-03.zh-CN.md)会拒绝 manifest 缺失但图文件仍在的普通读写；完整图冷加载会拒绝当前算法摘要不匹配的图。单机先停止业务写入、保留目录副本，再执行 repair 预检及显式 apply，核对重建结果与已确认版本；不要通过创建同名租户或直接写入来绕过错误。首次未发布 commit 的单机显式 recover 仍可用。重建只能使用现存有效对象，不能保证找回已丢失文件，也可能包含未曾确认的连续孤儿提交。摘要不匹配时应恢复已验证的数据或备份，不能直接改摘要使其通过。

Raft 中此类错误会停止故障副本应用并保留原 checkpoint，健康多数派继续服务。恢复正确文件或按成员替换流程用新 ID 重建，再核对重放结果；不要在故障副本上独立运行单机 recover/repair。旧程序不会获得这些保护，混部期间仍需保留原有审计和备份；2.3.0 的跨版本资格只覆盖[已验收窗口](raft-rolling-upgrade.zh-CN.md)，不扩展到任意历史版本。

同轮还修复了快照加载拼接虚假来源身份的问题。来源所有者与外部 ID 来源不同、且已有显式 `sources` 的数据，需核对原始身份和备份；受影响组采用全组维护升级，不得与旧解释的程序混部。已经被旧程序合并或持久化的虚假身份不会自动恢复，详见上述审核记录。

默认心跳 `GRAPHDB_RAFT_TICK=100ms`，选举等待独立使用 `GRAPHDB_RAFT_ELECTION_TICKS=30`，随机范围约 3–6 秒。该默认值容忍维护期间秒级 IO 长尾，也会延长异常失主检测；可恢复为 10 个 tick，但需在目标磁盘和负载下验收。

`GRAPHDB_RAFT_STREAM_SNAPSHOTS=true` 启用快照格式2。2.4.2 及之后版本默认启用，按远端能力回退到格式1；显式 false 强制旧内联传输，需要预留完整 JSON/base64编码与解码的内存。程序始终能读取旧格式1。格式 2 的数据库文件通过固定位置的文件视图生成，压缩不持有共享应用屏障；归档保存为校验过的磁盘文件，HTTP 传输不构建完整 JSON/base64 缓冲。接收端先核验 SHA256、长度与归档，再通过复制事务安装。失败暂停该副本的新提案，后台每五秒重试；读取和诊断仍可用。

`GRAPHDB_RAFT_MAX_SNAPSHOT_BYTES` 默认 512MiB，上限 1TiB，限制解压后的归档预算。提高预算需要同时核验磁盘容量、图加载内存和网络时间。流式快照私有 HTTP 收发期限为十分钟。固定文件视图仍会保留旧文件占用；图解码、单对象事务回滚和旧格式回退仍可能需要内存。

`GRAPHDB_RAFT_PROTOCOL_VERSION=2` 启用压缩和索引重建的准备/发布分离；协议 3 进一步支持 GC，在固定租户文件视图上扫描、生成待发布文件及删除清单。维护准备与 WAL 发布独立运行，结果按最多 1MiB 的块复制。发布核对租户版本、配置、代次及任务身份；状态变化时丢弃旧结果重新准备；同一任务连续三次冲突后，当前 Leader 暂停该租户的新变更并排空已受理 WAL，再于应用屏障外准备和复制结果，防止持续写入使维护永远排队。期间该租户的新写入返回 `429`，原因 `maintenance_pending`，附带重试提示；读取、任务入队/取消/重试和其他租户继续服务。取消任务或失去领导权时中止准备，随后恢复准入。记录 `maintenance_write_pause/maintenance_write_deferred` 事件及 `graphdb_ha_maintenance_writes_paused` 当前状态；结束、取消或失去领导权后恢复准入，换主/重启重新计数。GC 不使用新写入的磁盘准入阈值，仍需要实际临时空间；准备归档的删除清单最多 16MiB。最终文件发布和删除仍占用应用屏障，repair、导入及图恢复尚未拆分准备阶段。

先把每个投票副本和 router 升级到新程序，保持协议 1、流式快照关闭，再启用新能力。启用协议 2 或 3 的首个提案会检查全部投票副本的最高支持协议。提交相应协议日志或持久化格式 2 快照后，不能再用不支持这些格式的旧二进制打开目录。协议 3 GC 使用新的维护归档格式；最高协议为 2 的程序不能处理或原目录回退到它。协议最低要求会持久化；重启时不能通过把环境变量改回 1 来降级。回退应使用升级前完整备份与原二进制，在隔离环境恢复。滚动升级协调及混部窗口见[Raft 运维手册](raft-operations.zh-CN.md)。

本版修复了旧快照遗漏点号开头业务路径的问题，例如 `.hidden` 保存查询和点号开头的对象前缀。旧二进制不能安装包含这些路径的新快照；这类部署不在旧版回退和混部快照资格范围内。升级前先完成完整离线备份，混部期间不新增这些名称，并在所有副本升级后才使用；已有此类路径的部署需要单独验收升级流程。运行时根目录的控制、暂存路径仍保留给程序使用。

## 完整运行状态灾备

图备份 API/S3 备份继续用于逻辑图恢复，不包含全部运行状态。[单机与 Raft 自动备份](backup-automation.zh-CN.md)提供外部持久化调度、校验和演练，不替代以下完整离线归档。新增离线命令：

```sh
graphdb runtime-backup /backup/node.runtime --max-bytes 1099511627776
graphdb runtime-restore /backup/node.runtime --max-bytes 1099511627776
```

两条命令使用与 `serve` 相同的环境配置。归档必须在数据、WAL、Raft 根目录之外，文件权限为 0600；凭证和服务配置不在归档内，应由独立的配置/密钥管理保存。备份目标必须不存在，恢复目标必须为空。

完整归档包含数据目录的接入幂等身份、采集状态、保存查询、任务和配置，以及单机 WAL 或节点 Raft 元数据/快照文件。离线备份持有正常进程目录锁；正在运行的服务不能被此命令备份。恢复核对 SHA256、路径、解压预算、部署模式及节点/集群/分片身份，核对对象前缀，并在目标目录内暂存后发布。

[2.2.4 的恢复保护](product-p0-p1-review5-2026-10-03.zh-CN.md)同时持有 data、WAL 和 Raft 的独占锁；即使 data 目录空闲，只要独立 WAL/Raft 目录仍被占用，备份和恢复续跑都会失败。Raft 新增持久 `.lock`，恢复还锁定 `raft.db` 以保护仍使用旧程序的进程；发布期间也锁定新数据库文件。`.graphdb.lock` 和角色根目录 `.lock` 不属于恢复数据，不可删除或替换来解除占用。旧归档和恢复日志中的 WAL `.lock` 兼容读取，但不会覆盖目标锁文件。

可以沿用 WAL/Raft 位于 data 内的默认嵌套布局。迁移目录位置时，归档中父角色的对象不得落入另一个角色的子目录；发现这种冲突会在创建目标前拒绝恢复，应选择没有对象交叠的布局。最终文件在同一文件系统内以不覆盖目标的方式发布；并发出现的额外文件也会使恢复失败。归档校验保护文件传输，不代替图/WAL/Raft 的语义审计或完整集群灾备演练。

恢复准备或发布中断会留下恢复日志，普通服务拒绝启动。使用同一个归档再次运行恢复命令；程序核对归档和完整文件清单后续跑。发现额外文件或符号链接则拒绝处理，先由运维确认来源。不要手工删除恢复日志来绕过检查。本次恢复拥有的 `.runtime-restore-*` 暂存目录会在续跑时清理；发现其他残留目录时，确认没有恢复进程使用后再处理。

完整集群灾备需要停止目录组、数据组及入口，在一个一致的停机边界分别备份所有成员，保存拓扑与身份配置。恢复到隔离网络的空目录，保持节点身份和地址映射，恢复足够组成多数派的成员后再接入客户端。一个节点归档不等于完整集群灾备；此流程也不是在线一致性备份。跨部署迁移继续使用逻辑备份/API 导入，不能改写归档身份来把 Raft 目录变成单机。

## 诊断和告警

管理员 `GET /v1/diagnostics` 提供本地构建、部署模式、协调状态、磁盘、WAL、Raft 和问题摘要。可指定 `X-Tenant-ID` 获取最多 100 个本地任务。诊断是本地观察，失去 quorum 仍返回 `200` 和 `status=degraded`，不保证集群线性一致视图。

`/metrics` 同样能在失去 quorum 时读取。新增磁盘可用空间、准入状态、Raft 已知 Leader、应用积压和快照失败指标；任务失败计数表示本进程观察到的失败状态转换，重启后归零。已有 WAL、索引和请求指标继续保留。告警示例见[Prometheus 规则](../deploy/prometheus/graphdb.rules.yml)，积压阈值需要按实际业务调节。

监控应抓取每个节点的私有管理端口，不能只抓取 Leader 网关。`leader_known` 不是实时 quorum 证明；结合入口 readiness、所有副本状态和请求错误率判断。索引健康指标是最近一次检查结果，安排周期检查才能发现新损坏。Prometheus 的 `up` 和抓取失败告警应由监控平台配置。

后续诊断补齐 Raft 内部耗时、逐副本复制状态、独立 WAL/Raft 磁盘、准入并发与排队、catalog 迁移状态、router 缓存与上游错误、进程内存/GC。catalog 和 router 的本地入口同样在故障或 drain 期间可读。指标口径、采集配置和诊断示例见[诊断指标说明](diagnostics-metrics.zh-CN.md)；本轮实际验证见[诊断验证记录](diagnostics-validation-2026-10-02.zh-CN.md)。

## 受保护的部署示例

[单机模板](../deploy/production/standalone.yml) 仅发布 TLS 网关端口，数据和管理端口分离并限制在内部网络。[Raft 覆盖配置](../deploy/production/raft.override.yml) 同样取消裸后端端口暴露，管理入口独立代理。二者复用现有 [Nginx 认证契约](../deploy/nginx/graphdb.conf.example)。

```sh
docker compose -f deploy/production/standalone.yml config
docker compose --project-directory . -f docker-compose.raft.yml \
  -f deploy/production/raft.override.yml config
```

配置前必须提供已资格验证的镜像、TLS 证书目录和实现 `/verify` 契约的身份服务镜像；Raft 还需要随机共享 token。身份服务验证凭证、角色和租户后返回 `X-GraphDB-Tenant-ID`，拒绝未授权请求；网关覆盖客户端自行提交的租户头。模板不包含身份服务实现，不能在省略认证后用于公网。

旧 Nginx 模板按原始 `$request_uri` 分类角色，编码路径可能绕过写入角色检查。
部署时更新为保存规范化请求路径的新模板，执行 `nginx -t` 并重新加载；仅升级数据库
程序不足以应用此修复。规范化路径必须在鉴权子请求前保存，具体契约和回归门禁见
[安全部署说明](security-deployment.zh-CN.md)。

跨宿主机部署还需要真实私有地址、独立磁盘/故障域和加密私有传输。Raft 后端当前使用 HTTP，需通过受保护网络、加密隧道或内部 TLS 代理实现加密。生产环境的身份后端、证书更新、冗余入口和跨宿主机故障场景仍需环境验收。

### 写后校验读取失败

任务、配置等对象发布后若读取租约或租户版本遇到 I/O 错误，服务返回原始错误，写入结果未确认；不会仅因一次读取失败而删除对象。在 Raft 应用中，这类错误触发整个应用的持久化回滚，检查点保持原值。已明确发生租约失效或租户删除、重建的晚到写入仍会清除。单机请求返回错误后，更新对象可能已落盘：任务应先查询原任务 ID；对支持幂等键的提交或摄取，应保留原键重试。不应把 I/O 错误当作 CAS 冲突无限重试。

## Raft 离线恢复确认（2.3.8）

Raft 的 `runtime-restore` 必须显式增加 `--isolated-cluster-recovery`，否则恢复前拒绝操作。
此参数确认操作者已停止并隔离整个旧集群；它不会替你配置网络隔离，也不是安全身份验证。
恢复会回退 term、vote 和日志，禁止把旧身份恢复到仍在线的集群。在线替换副本使用新的 node ID 加入，
不能用这个参数绕过该约束。单机恢复不需要此参数。

```sh
graphdb runtime-restore /backup/node.runtime --isolated-cluster-recovery --max-bytes 1099511627776
```

完整 WAL 帧的校验失败仍拒绝启动：无法证明它未被确认，不能自动截断已接受的数据。
最后一段只有不完整帧尾部才允许安全截断。
