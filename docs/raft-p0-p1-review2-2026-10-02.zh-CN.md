## 行为回归

新测试位于复制层的 `membership_test.go`，原有该包只有磁盘日志测试，没有真实节点与成员并发场景。测试启动四个真实 Raft 节点，使用私有 HTTP 接口完成合法加入、提升和移除，并将已经受理的提案延迟提交，确定性复现日志顺序窗口；没有修改生产代码来插入测试延时。

- `remove` / `add_learner`：拒绝过期变更、返回该提案的冲突结果、保留三投票节点和正确地址；整组重启后继续写入，再完成正常提升/移除。
- 两个 `legacy` 场景：命令没有受理配置字段时，仍保护副本下限及已占用 ID。
- `snapshot_metadata`：真实断连、日志压缩、快照接收、阻塞与恢复图应用，检查后续成员地址仍持久化；同时验证退役记录与快照位置的边界。

修复前失败日志保留在 `/tmp/graphdb-p0p1-review2-20261002/membership-before.log` 和 `snapshot-before.log`，分别记录双投票配置、错误地址以及快照擦除后续地址。五个成员回归和原有磁盘重开测试在修复后通过。

另修正原有并发合批测试的调度前提：阻塞第一个图应用后，较晚进入的 HTTP 读取屏障和受理配置读取会合法等待这个提交，不能要求八个请求都已经越过屏障。首次竞争检查触发该测试超时，隔离复跑通过。测试现改为直接提交已受理命令，仍验证应用阻塞期间 Raft 继续多数派提交、独立响应、事务合批和重开持久性。真实 HTTP 并发行为仍由原有集成测试和部署门禁覆盖。测试命令通过标准请求头构造，再直接提案；修正过程中一次未标准化请求头导致的测试失败也保留在证据中。最后完整竞争检查通过，进一步固定到直接 Raft 提案的测试边界后，专项竞争复验再次通过。所有失败日志完整保留。
