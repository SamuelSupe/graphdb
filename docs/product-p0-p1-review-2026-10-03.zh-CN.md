# 产品 P0/P1 审核与修复

2026-10-03，基于正式版本 2.2.2 的提交 `d279a53ec87f7c24b46779f65ec6efbc6391aec0`，在 `GraphDB-raft-ha` 工作树继续审核。检查了单机与 Raft 的图加载、提交和事务回滚，成员配置与快照安装，分片迁移/取消/归属隔离，恢复传输、维护任务、对象备份及离线运行目录恢复。此前四轮审核保留原有版本与证据，本记录不替换历史资格验收。

本轮未确认新的 P0，确认两项 P1。该结论限于已检查路径和实际回归场景，不表示已经证明全产品不存在其他缺陷。

| 问题 | 触发与影响 | 修复 |
| --- | --- | --- |
| P1：S3 恢复切主后不能续传 | 首个恢复分块已经提交，Leader 退出。新 Leader 重新下载同一份备份，校验报告使用当前时间，导致输入 SHA256 变化；原任务被保存为 failed，不能续传同一恢复。 | 在已有复制上下文中使用固定业务时间。校验报告固定为任务受理时间，新 Leader 继续复制同一输入，单机报告仍记录实际检查时间。 |
| P1：损坏的图依赖被消费为普通任务失败 | 单副本的 manifest 引用的 commit 缺失或不可解码。压缩执行将读取错误保存为 failed，并推进 checkpoint；健康副本完成压缩，故障副本却永久消费同一日志，任务及持久化图布局发生分歧。 | manifest 解码错误与已引用图对象的缺失、解码、身份或版本校验错误登记到已有复制事务。即使任务处理层捕获返回错误，事务仍回滚，不推进 checkpoint；故障副本停止应用，健康多数派继续工作。 |

没有将业务错误全部升级为副本故障。未创建租户的初始 manifest、可选对象不存在和正常 EOF 保留原语义；没有复制事务的单机任务仍返回原有错误。修复不自动恢复已丢失文件，也不回溯重建旧程序已经消费的任务结果或副本分歧。

## 回归证据

在已有 HA 集成测试中增加两个行为场景，复用三个真实 Raft 节点及独立数据目录。故障注入使用已有对象读取包装边界，没有生产延时、开关或新的测试框架。

- `TestHAObjectRestoreResumesAfterLeaderLoss`：使用独立 MinIO 桶/前缀捕获含 2MiB 实体字段的 S3 备份，删除当前实体，受理恢复并多数派提交首个 1MiB 分块；停止 Leader，由新 Leader 完成原任务。检查全部副本恢复备份版本及完整实体字段、暂存清理、旧 Leader 重开追赶，并继续写入。
- `TestHAReferencedGraphFailureStopsReplicaUntilReplay`：分别注入一个副本的 commit 缺失与非 Parquet 内容，执行压缩；检查故障副本 checkpoint 不推进、任务仍 queued，多数派继续写入；解除故障并重开后，检查原压缩日志重放成功，图包含原实体和后续写入。

生产修复前，两项场景均失败：`s3-before.log` 明确记录 `restore input changed during transfer`；`graph-before.log` 中两个故障副本保存 failed，checkpoint 与健康副本相同，节点未报告故障。修复后的专项普通测试通过，分别见 `s3-fixed-final.log` 与 `graph-fixed.log`。S3 用例还加入现有 `scripts/object_backup_gate.sh` 的竞争检查，防止没有 S3 环境的普通单元测试跳过关键回归。
