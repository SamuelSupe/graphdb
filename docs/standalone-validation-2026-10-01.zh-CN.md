## 持续验收口径

direct 和 WAL 各运行三十分钟，四个写入者、十六个查询者、每批二十个应用组，每个写入者间隔五秒。使用现有持续验收工具，穿插 compact、GC 和索引重建；普通请求期限 120 秒，维护期限十分钟。持续阶段的读写缓存各为 2GiB，基础 HTTP 阶段的读取缓存为 1 字节，用于覆盖缓存淘汰后的行为。

现有工具允许 HTTP 429 作为背压拒绝，统计中保留成功、拒绝和错误。429 不计作成功写入，不重写为零拒绝。工具在持续时间结束、上下文取消时不计相应错误；没有取得 HTTP 状态的尝试另列为未分类，不能算作已确认成功。周期指标为累计值，最终汇总只采用每个操作最后一次记录，不重复相加。

两种模式各成功执行 5 次压缩、2 次 GC、2 次周期索引重建；此外各有 1 次准备阶段索引重建。严格报告的预热后索引状态样本中，direct 有 39 次、WAL 有 18 次暂时落后，最终均为 ready；读取样本没有版本落后或不可用。持续验收只验证本次负载下的已确认写入、读一致性和维护行为，不承诺最大吞吐或固定磁盘占用。

大图冷启动时，进程就绪不代表租户读取缓存已经加载完成。默认两秒追赶期限下，第一次完整导出返回 `503 reader_not_fresh`、`retryable=true`、`Retry-After: 1`；按该契约重试后返回最终版本的完整数据，深度审计和 SIGKILL 后再次重开均通过。首次失败日志及重试响应保留在证据中；未调高服务追赶期限掩盖此行为。

## 证据与边界

结构化结果见 [验收汇总 JSON](standalone-validation-2026-10-01.json)。原始证据归档位于 [单机验收证据包](../dist/graphdb-standalone-validation-20261001-6318b54b.tar.gz)，外层 SHA256 见 [校验文件](../dist/graphdb-standalone-validation-20261001-6318b54b.tar.gz.sha256)；包内 `SHA256SUMS` 验证各日志、报告和脚本。临时目录为 `/tmp/graphdb-standalone-verify-20261001-6318b54b`。

临时服务脚本复用 `scripts/release_gate.sh`，仅固定被测二进制、为两种模式分别启用 SDK/持续验收；改动差异随证据保留，仓库门禁脚本没有修改。Go SDK 的 GraphQL 调用在跨平台阶段加入临时程序；Linux arm64 的大图 GraphQL 由落盘重开检查单独验证。

macOS 数据目录通过真实路径启动；最初使用 `/tmp` 符号链接被目录安全检查拒绝，该失败及修正后的运行日志均保留。Linux amd64 使用模拟运行，只证明本次 HTTP、SDK 和恢复场景，不能据此推导原生 amd64 性能；macOS 也只执行功能冒烟，三十分钟负载只在 Linux arm64 上运行。

本轮验收针对单机本地磁盘、固定负载及上述备份环境。生产容量、低剩余磁盘、长时间饱和负载与云厂商 S3 环境需按实际部署继续验证。Raft 跨宿主机按用户确认仍保留待验收，不以本轮单机结果替代。
