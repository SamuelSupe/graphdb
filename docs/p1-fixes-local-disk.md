## 修复内容

| 问题 | 最终行为 |
| --- | --- |
| 覆盖恢复清空任务断点、原数据和本地备份 | 先在同一文件系统独立构建并校验快照、配置和索引，保留原有任务及备份，再通过持久化日志切换目录。中断后的启动先回退未提交切换；已提交切换保留新目录。 |
| 旧 WAL 跨租户清空、重建重放 | 租户代次保存在租户目录之外；受理绑定代次，发布时在租户锁内验证。旧代次进入 WAL 失败终态，不向新租户写入失败记录或实体。不带代次的旧 WAL 仅允许在初始代次重放。 |
| 本地备份随后续提交失效 | 清单只校验独立完整备份记录。兼容旧清单，在线 manifest 和派生索引不再成为恢复依赖。 |
| HTTP purge 与 WAL flush 的读视图死锁 | 租户管理写请求不再取得 HTTP 读视图；生命周期操作先暂停新受理、排空 WAL，再获取排他视图及租户锁。 |
| 不同参数任务被静默合并 | 只复用参数相同且未终结的任务；不同参数返回冲突。终态已持久化的任务不会因运行时标记稍后释放而被复用。 |

## 持久化和并发边界

- 保留原 Parquet、WAL 和公开备份格式，新增代次记录及私有恢复日志。
- 构建、排空 WAL、等待读视图和切换目录的锁顺序固定。恢复期间的租户维护锁也阻止并发配置、状态变更被覆盖。
- 多个目录重命名不是原子事务。新目录提交前保留旧目录；打开数据目录时在进程独占锁内处理未完成切换。
- 文件切换期间串行处理文件操作，防止任务状态在目录切换时丢失。已经打开的随机读文件句柄继续引用原 inode，其整个生命周期不会占住切换锁。
- 切换后失效 manifest、图、配置、索引目录等缓存，避免同版本旧数据被复用。
- 如果磁盘错误使切换回退无法完成，拒绝后续操作，避免新的确认写入在重启回退时丢失；需要重新打开目录并完成恢复。
- 恢复需要同时容纳旧数据、新数据和下载快照。原有本地备份及任务历史继续保留，远端快照仍可独立用于空目录恢复。
