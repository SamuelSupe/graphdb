分支：`codex/local-disk-v2`。以本轮开始时的已有迁移、备份和性能改动为基础修复；没有提交、推送或合并。

## 修复结果

| 问题 | 修复后的行为 |
| --- | --- |
| 已发布恢复的重试覆盖后续写入 | 恢复结果和租户代次随新目录发布。任务终态写入失败后，重试只补做收尾，保留后续确认写入；源备份被删除也可以收尾。若租户已再次恢复，重试失败并保留现状。 |
| 同版本恢复后旧游标混读新图 | 实体、边、HTTP 热缓存及图回退游标都绑定持久化租户代次。旧游标明确拒绝；清理编译扫描缓存，并在命中缓存前验证目录身份。固定目录/文件丢失时不回退到其他图。 |
| 慢下载加恢复阻塞其他租户 | 暂存文件只在创建时占用目录锁，下载、解码期间只保护文件生命周期。目录访问和恢复发布使用已有 x/sync 中可取消的信号量，排队能响应请求超时。 |
| GC 等待查询时无法取消查询 | 查询列表和取消接口直接访问本进程运行查询注册表，不申请图读视图或等待磁盘生命周期检查。保留租户 ID 校验及查询归属检查。 |

同步保留远端快照 SHA256 断点，避免分阶段构建丢失恢复源身份。
使用已有 `golang.org/x/sync v0.20.0`，从间接依赖声明移为直接依赖；没有引入新依赖版本。

### 兼容与边界

- 现有 Parquet/WAL 格式不变；新增恢复任务断点及可选游标字段。
- 初始租户代次继续接受旧格式游标。正常提交、同代次索引更新及已有目录保留机制不使游标跨版本分页失效。
- 恢复或清空后，旧游标需要从第一页重新开始，不能仅因版本号相同就继续。
- 旧版本已发布但缺少可验证代次/结果断点的失败恢复任务，重试会明确失败，不再次覆盖数据。
- 下载不持有目录锁；恢复保留任务/备份并切换目录时仍有共享目录临界区。这次没有宣称所有维护操作完全不影响其他租户。
- 原工作区及已有 GraphDB-local-disk 工作区保持原样。

## 回归测试

在已有测试文件中补充 6 项针对实际缺陷的行为测试：

1. 终态写入失败后，在 v2 写入确认、备份清单删除、目录重新打开后重试；保持 v2 和新实体。另验证再次恢复后的旧重试不会覆盖新代次。
2. 暂存文件保持打开时完成另一租户恢复，随后文件仍可写入；关闭数据目录仍等待暂存文件释放。
3. 目录发布排队期间，文件读取遵守 deadline，取消后后续读取正常。
4. 索引路径和图回退路径均拒绝恢复前的实体/边游标，新代次分页仍正常，初始代次旧游标仍兼容。
5. 固定目录缺失时，即使当前版本号一致且旧缓存仍热，也不默默回退。
6. GC 等待运行查询时，HTTP 列表与取消正常，其他租户不能取消该查询。

原审查中的暂存文件探针依赖旧 RWMutex 内部结构。本轮将其替换为上述公开文件/任务行为断言，直接验证下载保持打开时恢复可以完成，而非要求修复后的恢复仍进入旧阻塞状态。
