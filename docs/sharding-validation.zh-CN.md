# 分片扩容验收记录

日期：2026-10-01（Asia/Singapore）。独立 worktree：`GraphDB-raft-ha`，分支：`codex/raft-ha`。本次在原有单机和单组 Raft 实现上增加租户分片，没有发布或推送远程。

## 环境

- OrbStack Linux aarch64，Go 1.26.7，最终二进制 SHA256：`849e13cd1b165e6ab9f2ae83bcb5659db916a6b51c860b5c95d9cb073206bbdd`。
- 使用 `docker-compose.sharded.yml`，先启动三副本目录组和三副本数据组 A，再实际新增三副本组 B。九个副本使用独立持久卷、真实私网 HTTP 通信，入口是独立 `serve-router` 进程。
- 最终测试镜像 ID：`sha256:99794eac7076e5e908b2be8b5454dca5d63b3362f7a001aae2840d055298f3e3`。
- 同时运行两个默认单机服务，分别使用 direct 和 WAL；扩容后共十二个进程，使用相同二进制镜像。另以同一最终镜像复核原有单组三副本部署和两个单机服务。
- 测试期间快照间隔 5 条、WAL 合批间隔 200ms，迁移包含约 1.95MB 的接入载荷及终态受理记录，超过单个 1MiB 传输块。

## 实际运行结果

| 行为 | 结果 | 证据 |
| --- | --- | --- |
| 新增数据组 | PASS | 创建租户 A 后新增组 B，A 的位置和 epoch 保持不变；新租户 B 分配至新组并读写成功 |
| Share-Nothing 与单机共存 | PASS | 独立目录组及数据组、两个单机服务同时运行；相同租户 ID 和幂等键的内容分别保持独立 |
| 迁移中目录切主 | PASS | 目标组暂停后提交迁移，目录持久化 copy 阶段及错误；终止目录 Leader 后新主继续完成迁移 |
| 迁移中目标切主 | PASS | 观察到目标暂存分块后终止其 Leader；剩余多数派继续安装并激活，旧节点随后恢复 |
| 版本和接入身份 | PASS | 迁移后 commit 幂等重试返回原 version=1；min_version=2 查询成功；原 writer-ID 查询 URL 返回相同 accepted_lsn 和 committed 状态 |
| 源数据清理与过期请求 | PASS | 源租户目录不再包含图对象；旧 epoch 请求向源组写入返回 409 |
| 迁回旧组 | PASS | 租户由 B 迁回已清理的 A，epoch 继续推进，重新写入成功 |
| 分片故障隔离 | PASS | 暂停 A 的全部副本，B 的写入和两个单机服务的读取仍正常 |
| 取消迁移 | PASS | 目标不可用时取消 copy 阶段，源先恢复 active 并提高 epoch；目标恢复后清理完成 |
| 防止角色降级 | PASS | 关闭一个数据副本，复用其卷但删除分片角色参数，启动明确拒绝；恢复原配置后读取正常 |
| 入口 OpenAPI | PASS | 通过入口取得契约文件，包含新增集群迁移接口 |
| 原单机/direct/WAL 行为 | PASS | commit / 接入在 SIGKILL 后恢复；WAL 202 受理恢复后仅发布一次，幂等身份不变；compact、GC 和停机离线 CLI 可用 |
| 原单组 Raft 行为 | PASS | 多数派 WAL 受理后终止 Leader，新主接管；两个单机服务持续读取；删除 Raft 参数时副本拒绝单机服务及离线写入 |
| 旧目录保护 | PASS | 已有单机目录拒绝直接 bootstrap Raft 后仍可按单机打开；副本恢复原配置后正常重启 |

运行日志和逐项结果保存在本机 `/tmp/graphdb-sharding-runtime/` 与 `/tmp/graphdb-sharding-dual-mode/`。验收使用的服务、网络和持久卷已清理，不影响其他 OrbStack 工作负载。

## 尚未验证的范围

支持按完整租户扩容和显式迁移，没有单个租户内部切分、跨分片查询或自动热点均衡。迁移期间暂停该租户读写，其他租户正常服务；没有增量不停机搬迁。

尚未完成跨宿主机或故障域、真实磁盘故障、磁盘耗尽、长时间负载、生产容量和大租户内存/快照预算资格验证。本机九个副本不能代表机架或宿主机故障验证。迁移分块解决单条提案大小，导出和安装仍需在内存中组装完整租户，并受各组快照预算约束；目录可用性仍是入口准入条件。

部署、扩容、迁移、取消和旧组接入方法见 [分片运行说明](sharding.zh-CN.md)。原单组的 S3、维护及成员替换验证见 [Raft 验收记录](raft-ha-validation.zh-CN.md)；本次没有重复进行外部 S3 灾备资格验证，也没有发布制品或验证跨版本混部。
