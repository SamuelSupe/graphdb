# Raft 正式发布准备

本分支继续支持默认单机、单组 Raft 和按租户分片的 Raft。当前工作是发布准备，没有创建新发布标签、更新远端或发布正式资产。`VERSION` 及 SDK 继续对应已发布的 2.1.2；发布新 Raft 版本前统一选择并更新版本号。

## 本轮实现

- 恢复输入按最多 1MiB 的块多数派持久化，最后校验完整 SHA256 并通过原有事务发布。支持超过单条提案限制的恢复、换主续传、终态清理和取消；输入完整复制后，接管节点无需重新读取备份源。租户清空或替换会使旧恢复失效，不能重新写入旧数据。
- 复制提交任务时登记所属租户，使不存在目标图的冷恢复任务也能被后台发现；试恢复不创建目标图。恢复演练的空查询模板列表持久化后仍按未配置处理。
- 修复维护期间入口误摘 Leader：就绪检查确认新的多数派，不等待应用阶段；图读写继续等待完整应用屏障，不能读取过时数据。
- 将普通 Raft 请求的内部等待预算从一分钟调整为两分钟，避免在客户端允许等待的维护窗口中提前截断；更短的客户端期限仍生效。维护造成的长尾仍需单独资格验证。
- 等待应用屏障前先读取有上限的请求体，防止维护等待耗尽 HTTP 读取期限而将正常请求误报为 413；真实连接回归覆盖该场景。
- 将此前临时部署检查迁入 `scripts/raft_gate.sh`：同镜像单机 direct/WAL 与 Raft 共存、SIGKILL 恢复、幂等身份、真实网络分区、角色/目录防误用、36MiB 备份恢复，以及新增三副本分片、迁移中断/返回/取消和故障隔离。
- CI 增加真实容器 Raft/分片门禁，正式发布流程追加三十分钟 Raft WAL 混合读写与维护验证，报告保留镜像和二进制摘要。
- 发布包加入两种 Raft Compose、HAProxy 配置、门禁脚本/场景和验收证据；单机部署材料继续保留。
- 发布镜像和归档使用相同版本、提交时间和编译参数；归档验证要求 Linux amd64 二进制摘要与 Raft 门禁实际测试的二进制一致。
- [运维手册](raft-operations.zh-CN.md) 明确监控、入口保护、整组升级、回退边界和故障恢复。

## 正式发布前仍需完成

| 项目 | 状态 / 要求 |
| --- | --- |
| 独立宿主机与故障域 | **待验收**：目前没有三台独立测试节点，按用户决定保留此项；需验证宿主机退出、网络故障和恢复，不以同机容器结果替代 |
| 版本与发布交付 | 待选定版本并统一 VERSION、SDK、OpenAPI、变更记录和发布说明；随后验证提交/标签、远端工作流、下载资产及两层校验和 |
| 跨版本升级矩阵 | 当前只保证本次候选的同版本重启及新版读取旧格式；使用整组维护升级。旧版不能执行恢复分块日志，不能原目录降级；尚未对混部资格验收 |
| Raft 与真实 S3 联测 | 三副本手动备份、换主/整组重启、全新目录恢复、试恢复、覆盖恢复与恢复证明已通过小图联测；大 S3 传输、S3 中断与恢复仍待验收 |
| 内部自动 S3 备份 | 当前 Raft 不支持，启用请求明确报错；使用外部调度调用集群备份接口。单机自动备份继续支持 |
| 真实容量与生产负载 | 需要大图、多租户、迁移/恢复交错、低剩余磁盘与慢副本的容量基线。三十分钟小规模正确性验证不构成容量承诺 |
| WAL 性能 | 先前五副本 WAL 有窗口低于基线，且部分增益小于 A/A 波动；仍不做统一吞吐提升声明，数据见性能补充验收 |
| 快照与恢复资源 | 分块恢复解决单条提案限制，完整快照封装、备份准备和图解码仍需内存；默认快照预算 512MiB，完整快照流式网络协议未实现 |
| 生产环境接入 | 三个独立副本故障域、冗余入口、受保护/加密私有传输、备份恢复演练与容量告警需按实际环境落地 |

本机实测结果见 [发布准备验收](raft-ha-validation.zh-CN.md#发布准备补充验收)。已有 [单机容量说明](../release/capacity-envelope.yaml) 只针对其记录的单机版本和范围，不能直接用于 Raft 集群。所有未完成项继续标记待验收或未资格验证。
