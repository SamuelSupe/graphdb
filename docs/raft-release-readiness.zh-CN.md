# Raft 2.2.4 发布与部署验收状态

2.2.4 纳入下述候选修复、外部备份 worker、快照捕获与维护传输优化。历史候选报告保留其原构建和失败/通过状态，不代表本次发行二进制资格；最终交付以 [2.2.4 验证](validation-v2.2.4.md)、标签工作流和包内证据为准。性能候选的四次入口 503 仍为 FAIL，整体吞吐与跨宿主机资格仍未通过。

本轮[完整测试与修复](full-validation-2026-10-03.zh-CN.md)发现并修复编码路径的网关角色绕过，非 UTC 类型时间的 Parquet 内容校验不一致，以及校验 I/O 错误误删已发布对象。均属于未发布候选；最终验证状态以该记录为准。

2.2.2 合并默认单机、单组 Raft 和按租户分片的 Raft。`VERSION`、SDK 和 OpenAPI 已统一为 2.2.2。发行提交、实际工作流结论和资产核验以 [版本验证](validation-v2.2.2.md) 与 GitHub Release 为准；本页保留实现过程和尚未完成的部署验收。

发布后的 [2026-10-03 整体 P0/P1 审核](product-p0-p1-review-2026-10-03.zh-CN.md) 确认两项 P1：S3 恢复在 Leader 退出后无法续传，以及副本缺失或损坏已发布图的依赖时将复制任务保存为普通失败。本轮修复和回归属于尚未发布的候选，已发布的 2.2.2 不包含这两项修复；候选的实际验证范围以该审核记录为准。

后续 [整体审核](product-p0-p1-review2-2026-10-03.zh-CN.md) 另修复三项 P1：manifest 丢失被误判为空图、有效快照未绑定已发布摘要，以及快照加载制造来源身份并合并独立实体。以上修复仍属于未发布候选。来源身份修复改变受影响数据的解释，相关数据组不在旧程序与本候选的混部滚动资格内；正式发布前需单独确定兼容与升级窗口。

[迁移后续审核](product-p0-p1-review3-2026-10-03.zh-CN.md)又修复三项 P1：非法源图被复制并安装、离线覆盖复制失败先删除旧目标，以及损坏索引目录使整个目标组停止应用。复制改为暂存和完整校验，本地发布复用恢复日志；Raft 非法输入在修改代次前拒绝。仍属于未发布候选，跨宿主机和新双版本滚动矩阵保留待验收。

2026-10-02 的 [P0/P1 审核与修复](raft-p0-p1-review-2026-10-02.zh-CN.md) 确认并修复四项 P1，涉及副本配置分歧导致的确认写入/任务丢失，以及 WAL 背压导致所有副本停止应用。此前候选归档和镜像属于修复前的历史验收对象；正式发布需从修复后的提交重新构建并验收交付资产。

本轮[可用性与滚动修复](availability-rolling-validation-2026-10-04.zh-CN.md)修复持续写入时追平检查的采样顺序，以及压缩扫描在租户写锁内阻塞前台提交的问题。相关竞争检查、两个已限定旧来源的完整滚动矩阵、协议 3 同构建串行重启及单机三十分钟维护负载通过。三副本维护压力测试出现持久化路径长停顿和选主期间的请求错误，仍未通过可用性长测，属于未发布候选；跨宿主机验收继续待完成。

后续[三副本三十分钟长测复验](raft-long-validation-2026-10-04.zh-CN.md)再次失败：24,071 次操作、407 次操作指标错误、456 条错误事件，多次换主。共享 VM 资源压力和持久化长停顿仍需隔离对照；未改变实现或放宽门禁，可用性发布阻断继续保留。

本轮[可用性缺陷修复与复验](raft-availability-fixes-2026-10-04.zh-CN.md)修复旧快照清理导致节点失活、诊断被 Raft 阻塞、读写入口取消失效和积压误判。最终候选的 Linux HA race、单机/Raft/分片门禁、固定旧候选的混部滚动矩阵和三十分钟维护负载通过：62,029 次操作、操作指标错误和错误事件均为 0。旧对照与中间候选失败仍保留；本轮通过仅针对固定未发布构建和本机范围，没有容量或全版本升级资格，跨宿主机、24/72 小时、GitHub CI 和发行资产仍待验收。

## 历史候选实现与验证过程

[迁移与 Raft 快照后续审核](product-p0-p1-review4-2026-10-03.zh-CN.md)继续修复三项 P1：已确认迁移分块的本地丢失或变化被消费为普通拒绝，损坏的已发布图被打包并安装为校验和正确的 Raft 快照，以及错误前缀重启/快照导致已确认数据不可见。分块摘要随 ownership 多数派保存，快照在固定源视图和解码目标上冷验证图及对象前缀后才发布；目录及新命令绑定原 `GRAPHDB_PREFIX`。旧进行中迁移需要完成或取消，目标组升级齐后发起新迁移；仍是未发布候选，没有新增双版本混部或跨宿主机资格。

同日 [第二轮审核](raft-p0-p1-review2-2026-10-02.zh-CN.md) 继续修复三项 P1：并发移除突破三投票副本下限、重复加入覆盖成员地址，以及异步安装旧快照擦除后续成员地址。成员变更现在按日志顺序核对受理配置，并等待对应请求的持久化结果；快照成员元数据与配置原子保存。

[第三轮审核](raft-p0-p1-review3-2026-10-02.zh-CN.md) 修复两项后台命令竞态：租户清除后的旧任务和迁移清理后的旧 WAL 发布曾因对象不存在而停止 Raft 应用。过期任务现在按业务冲突消费日志，分片 WAL 发布在生效时核对归属状态和代次；实际存储损坏仍保留故障处理语义。

[第四轮审核](raft-p0-p1-review4-2026-10-02.zh-CN.md) 修复两项 P1：本地读取失败被保存为普通任务失败，以及损坏的导入源被发布为成功导入。对象读取错误纳入复制事务；Raft 受理时保存源摘要，Leader 核对后将 SHA256 写入执行日志。副本上的源缺失或变化使该副本回滚并停止；Leader 准备阶段发现源变化则保存一致失败、不发布图数据。另修复成员变更在 Raft Advance 前过早回复造成下一变更被忽略的窗口。

后续 [故障隔离与迁移验收](raft-isolation-validation-2026-10-02.zh-CN.md) 增加维护公平推进及单租户写入暂停、目录失联时已知路由的有界回退、固定磁盘视图分块迁移、协议 3 准备 GC，以及控制消息独立传输队列。维护发布的回滚记录按有界批次持久化；默认选举等待改为约 3–6 秒，心跳保持 100ms。早期持续负载发现的错误保留 FAIL，各二进制的实际结果及尚未完成项以该记录为准。

根 Makefile 的版本注入路径已与当前 Go 模块和 Dockerfile 对齐，避免生成带 `dev/unknown` 的产物而使构建身份和滚动目标无法核对。此修复不等于发行资产资格，最终归档、镜像和下载资产仍需从发布提交重新构建并核验。

- 恢复输入按最多 1MiB 的块多数派持久化，最后校验完整 SHA256 并通过原有事务发布。支持超过单条提案限制的恢复、换主续传、终态清理和取消；输入完整复制后，接管节点无需重新读取备份源。租户清空或替换会使旧恢复失效，不能重新写入旧数据。
- 复制提交任务时登记所属租户，使不存在目标图的冷恢复任务也能被后台发现；试恢复不创建目标图。恢复演练的空查询模板列表持久化后仍按未配置处理。
- 修复维护期间入口误摘 Leader：就绪检查确认新的多数派，不等待应用阶段；图读写继续等待完整应用屏障，不能读取过时数据。
- 将普通 Raft 请求的内部等待预算从一分钟调整为两分钟，避免在客户端允许等待的维护窗口中提前截断；更短的客户端期限仍生效。维护造成的长尾仍需单独资格验证。
- 等待应用屏障前先读取有上限的请求体，防止维护等待耗尽 HTTP 读取期限而将正常请求误报为 413；真实连接回归覆盖该场景。
- 将此前临时部署检查迁入 `scripts/raft_gate.sh`：同镜像单机 direct/WAL 与 Raft 共存、SIGKILL 恢复、幂等身份、真实网络分区、角色/目录防误用、36MiB 备份恢复，以及新增三副本分片、迁移中断/返回/取消和故障隔离。
- CI 增加真实容器 Raft/分片门禁，正式发布流程追加三十分钟 Raft WAL 混合读写与维护验证，报告保留镜像和二进制摘要。
- 发布包加入两种 Raft Compose、HAProxy 配置、门禁脚本/场景和验收证据；单机部署材料继续保留。
- 发布镜像和归档使用相同版本、提交时间和编译参数；归档验证要求 Linux amd64 二进制摘要与 Raft 门禁实际测试的二进制一致。
- [运维手册](raft-operations.zh-CN.md) 明确监控、入口保护、已验证窗口的滚动升级、历史不兼容版本的维护升级、回退边界和故障恢复。
