# Raft 可用性缺陷修复与验证（2026-10-04）

修复三处具体可用性缺陷，最终候选三十分钟 Raft 维护负载结果 **PASS**。单机、Raft 和分片继续共同支持。本轮修改属于 `codex/raft-ha` 未发布工作树，没有提交、推送或发布。机器可读证据见 [JSON](raft-availability-fixes-2026-10-04.json)。

## 修复与保护边界

- 旧快照删除失败曾使健康复制节点停止运行或无法重新启动。清理改为单个后台任务，每五秒重试并保留诊断；只删除持久化且已应用位置之前的文件，保留恢复中的快照。启动失败孤儿按文件身份重试，避免误删后来原子替换的同名快照。真正的日志、快照持久化和恢复错误仍停止相应副本。
- 指标采集和 JSON 诊断曾同步等待 Raft 状态，持久化阻塞使监控请求也卡住。每秒单任务采样，周期诊断读取带年龄的缓存；本地错误和持久化提交位置实时读取。采样超过十秒暴露过期问题并可告警。健康、控制接口、成员变更和升级预检仍使用实时状态，缓存不作为多数派证明。
- 读写入口的同步状态检查曾阻塞请求取消；提交/应用交错采样的无符号减法还可能误判积压。入口使用本地持久化提交位置并将负差值限为零，保留 1024 条或 64MiB 的积压阈值。强读仍要求 ReadIndex、多数派和应用屏障，写入仍先持久化再确认。
