# 大图分片实施说明

适用于 **GGraphDB 2.6.0-preview.1** 的大图分片预览。2.5.0 和 2.5.1 提供协议 5 预览。协议 6–11 的 WAL、回收和分裂能力见[分片 WAL 接入](partition-wal-ingestion.zh-CN.md)，启用时按[升级步骤](partition-wal-ingestion.zh-CN.md#显式启用与升级)操作。完整目标见[设计](large-graph-sharding-design.zh-CN.md)，本次预览的负载边界见[验证记录](validation-v2.6.0-preview.1.md)。

## 已实现路径

- 租户仍是一张图；目录定位 home group，图控制状态管理 256 个 SHA-256 虚拟分区。普通租户保持原路径。
- 数据采用有校验和的不可变分页树；更新只改受影响路径。实体、边主记录、正反邻接、别名、全局身份/unique/关系基数目录和兼容逻辑摘要分别保存。提交校验只加载有界依赖闭包。
- 事务规划按数据组批量读取实体主键及身份、unique 和别名目录。在同一不可变根向量上，依赖闭包和变更生成共用目录结果，包括未命中的键。所有者校验、分区变更及摘要沿用原契约。
- 图控制组串行决定事务，输入分块多数派落盘。最多四个并发准备 RPC，恢复时复用已经持久化到控制组的准备结果。全部准备成功后原子发布统一版本和根向量，再以最多四个并发 RPC 完成参与者收尾。幂等请求保留原结果，结果未知时查询持久状态。完成后删除受理输入并缩小收据。
- 同一 Raft 应用窗口内，相邻的小型分区准备、收尾及数据分区 GC 步骤可共用回滚日志和落盘屏障。每条命令仍按原日志顺序执行，整批持久化后才返回结果。
- 批次 ingest 的完整请求先进入 home group 的复制受理队列，WAL 模式多数派持久化后返回 `202`。排队独立于活动事务，每图按受理日志顺序执行；终态结果随图决定持久化，Leader 切换或进程重启后补齐队列状态。支持版本条件、实体/边前置条件、atomic/best_effort 和原身份重试；`full_sync` 在受理前拒绝。
- 实体点查、基于轻量 ID/类型目录的全局有序实体扫描、结构化查询及查询 NDJSON；包括正向、反向和双向邻接、现有 lazy 引擎支持的遍历、路径、排序和聚合。无法执行的查询返回明确错误，不加载整图兜底。
- `min_version` 的 JSON、请求头和 URL 解析复用原 API；同一图版本复用持久读取租约。分页游标绑定租户 generation、版本和查询，续页临近到期时续租，跨写入与搬迁保持原版本。
- 旧租户按维护窗口流式转换，保留原版本、内容摘要、记录时间及旧 direct-commit 幂等结果。转换前要求当前版本的分页索引和摘要，缺少时在改变目录状态前拒绝。成功后分批清理旧图、索引和原请求正文，保留租户管理元数据。此前已完成退役的分片租户也会补扫旧字段、边、反向边与实体索引目录。
- 在线分区搬迁：先复制当前及仍受租约保护的根可达页，持久化捕获新增页，再阻止新图事务、复制最终增量并隔离源。目标 Leader 分批校验页，Raft 只推进检查点并安装已验证的根，最后切换 epoch 和布局 revision。搬迁不改变图版本或 `data_hash`。切换前的错误写入搬迁状态并记录日志。写入栅栏阶段持续失败 30 秒后尝试取消，源端恢复与目标清理分开推进。切换后只向前恢复。源副本等待最长查询期限后分批退役。
- GC 保护当前根、有效 pin 和准备事务；分批收集有效租约后，仅在安装分区保护边界时暂停写入。之后边写边清理历史视图、标记和回收。启动栅栏超过 30 秒且仍失败时取消本轮，恢复写入后清理临时标记。新准备产生的页在同一复制事务内加入保护集合。GC 与迁移互斥，支持手动触发及租户 GC 周期；协调状态和临时标记均可恢复。
- 协议 9 数据组启动的 GC 支持将待合并的页哈希随分区状态持久化，减少写入期间更新临时标记树产生的文件。快照校验同时检查分区状态内的哈希和标记树。
- 协议 10 由数据组 Leader 在应用锁外枚举 GC 扫页候选，由 Raft 应用核对清单的游标和最新保护集合。home group 可在 GC 步骤运行时规划下一批 WAL，步骤结束后顺序提交。
- 协议 11 的数据组在新分区准备命令中启用均衡叶页分裂。已有叶页溢出时，在页预算内选择最接近按行数平分的分界。旧日志按各自的修订号重放，已准备的事务继续使用持久化的页根。
- Raft 捕获及安装快照同时验证分区根、准备根、受理输入、分页、迁移增量和 GC 引用。验证针对暂存视图，失败不会替换原目录。

## 管理接口

管理请求使用 Router 的 Bearer 令牌。目录组、home group 和目标数据组使用协议 5 或更高版本，每个数据组至少三个独立副本。协议 5 预览版的日志可继续重放。使用分片 WAL 的 home group 按[升级顺序](partition-wal-ingestion.zh-CN.md#当前范围)切到协议 6。启用[受理正文复用和终态回执去重](partition-wal-ingestion.zh-CN.md#磁盘和快照)需要 home group 使用协议 7。以下示例的地址和组 ID 按部署填写。

```http
POST /v1/cluster/graphs
Authorization: Bearer <operator-token>
Content-Type: application/json

{"tenant_id":"big","data_groups":["data-a","data-b"]}
```

租户须已存在，目标数据组数量为 2–256。非空旧图先通过现有 `POST /v1/indexes/rebuild` 准备当前版本的分页索引，必要时先 compact 旧单体快照。接口返回 `202` 后通过下列接口查看转换阶段或图描述；错误写在 `partition_error`，后台按持久化位置重试。

```http
GET /v1/cluster/graphs/big

POST /v1/cluster/graphs/big/partitions/42/move
Content-Type: application/json

{"target_group":"data-c"}

GET /v1/cluster/graphs/big/partitions/42/move

POST /v1/cluster/graphs/big/partitions/42/cancel
Content-Type: application/json

{"move_id":"<id-from-status>"}

POST /v1/cluster/graphs/big/gc
GET /v1/cluster/graphs/big/gc
```

新增目标组先使用现有分片注册接口注册。搬迁和 GC 返回 `202`，进度随图控制状态复制。相同搬迁目标或正在运行的 GC 会返回已有操作。每图只运行一个搬迁；搬迁的 `cleanup` 阶段保护进行中的旧位置读取，结束前不能开始下一次搬迁。

## 当前预算

| 边界 | 当前实现 |
| --- | --- |
| 虚拟分区 | 固定 256，初始均匀分配到指定组 |
| 单个实体、边或目录值 | 1 MiB |
| 单次请求正文 | 8 MiB；不拆散原子提交 |
| 分区变更 | 最多 4096 行、8 MiB |
| 变更依赖闭包 | 最多 8192 个实体/边、64 MiB、32 轮；读取另受 RPC/字节预算约束 |
| 查询 | 最多 2048 个分区读取 RPC、64 MiB 返回数据、2 分钟；复用引擎访问数量等限制 |
| 同一 Router/客户端 | 每租户最多 8 读、1 写，进程上限 32 读、8 写。超额返回可重试的 429 |
| 单次分区读取 | 最多 128 个 key，或 256 行扫描；每组可合批至多 32 个分区请求，整批返回数据上限 4 MiB。多 key 请求内解码页缓存按估算另限制为 4 MiB、128 页 |
| 读取租约 | 同一租户版本共用一份，临近过期续租。每个游标最多 5 分钟有效，租约另保护 2 分钟的进行中查询 |
| 搬迁 | 每批最多 32 页、4 MiB，一次 Raft 提交。安装每步最多校验 32 页 |
| GC | 每步有界标记、扫描及删除；删除数据有 8 MiB 批次预算 |

home group 使用协议 7 时，GC 另清理未被活动事务认领的暂存输入，最多 32 个文件、8 MiB 一步。启动后的历史回执清理只删除已有完整终态回执对应的重复事务，详见[磁盘和快照](partition-wal-ingestion.zh-CN.md#磁盘和快照)。

控制组仅在首次访问版本或租约临近过期时写入租约，并按需保存视图。读取当前图描述仍通过控制组的 ReadBarrier，Router 用 ETag 复用未变化的描述。数据组直接读取已发布的不可变根，缺页或 epoch 不匹配时才等 Raft 应用后复核。只读分片 RPC 遇到连接失败或 503 时重新发现 Leader 并重试一次。

这些是保护上限，不是已验收的大图容量参数。来源全量清理、超大级联删除等操作可能超出提交闭包预算，需要后续维护任务。逻辑摘要维持 `sha256-shards-v2`；单叶更新仍可能重算该逻辑桶，不能视为恒定成本。

## 尚未实现及使用边界

新批次的来源全量对账 `full_sync`、import、collector/deadletter 管理、GQL/GraphQL、边扫描/导出、在线整图备份恢复、clone、完整租户生命周期、配置写入和带存量数据的 schema 修改返回 `501 operation_disabled`。分片增量 ingest 需 home group 启用协议 6，并兼容转换前保留的批次状态和幂等收据。全组停机归档可用于[离线集群恢复](product-operations.zh-CN.md#大图分片离线集群恢复)。

协议 7 可以为新受理的分片批次配置[终态回执保留期](partition-wal-ingestion.zh-CN.md#终态回执保留期)，既有回执继续沿用原规则。转换发布前的取消接口、超级节点 segment、hash 范围继续拆分、home group 搬迁和已用数据组的自动排空尚未完成。目录保守保留图关联，注销曾关联的组可能仍被拒绝。转换已进入初始化后应排除错误并继续，不得手工删描述或改目录强行恢复旧模式。

预览用于隔离环境试用和资格验证。依赖上述接口的租户应继续使用原部署。生产部署中的三副本需要独立故障域。

## 稳定性修复验证

对照源码为 `61a3bca`。40 个实体、每页 10 条时，旧版第 2 页复现 `entity scan directory is missing`。错误的触发条件是游标已经越过一个有数据分区的最后一行。新版将该分区视为已扫完。九节点 HTTP 回归覆盖 `/v1/entities` 和 match 两个入口，并让第二页实际越过前一个分区。

| 问题 | 核对与修复 |
| --- | --- |
| 首页与断开请求累计 pin | 旧版逐请求建立 pin，达到上限还会读取所有旧 pin。新版通过版本租约消除逐请求创建和释放。测试预置 4096 个旧 pin，连续访问首页仍只新增一个共享租约。 |
| 搬迁安装阻塞 Raft apply | 旧版在 apply 内完整扫描目标根。新版在目标 Leader 上分步验证，再复制检查点。注入目标缺页，校验在提案前失败，补回后可从检查点继续。 |
| GC 长时间栅栏与历史视图放大 | 旧版 prune 会阻塞写入，发布与收尾各保存一次视图。新版仅按需保存租约视图，分批收集与清理时允许写入。测试在 prune 阶段完成提交。 |
| 后台串行且失败不可见 | 调度最多并行推进 8 个租户，每租户同一时刻最多一个任务。失败进入日志，搬迁进度包含错误，切换前长期失败可回到源端继续写入。 |
| 每次读两次 Raft 写 | 现有有效租约直接复用。首页和点查不再提交 release，游标续页在租约临近到期时续租。 |
| 查询多次串行扇出 | 目录扫描在分区侧按 kind 筛选，按数据组合批读取扫描头和实体主记录。 |
| 单个慢租户占满 Router | 读取描述前按租户及读写类型准入，多个租户独立占槽。写入已被其他事务占用时可快速返回 429。 |
| 描述每次解码 | 数据组在应用图命令和安装快照时使对应缓存失效，Router 用条件请求复用已验证版本。 |
| 搬迁逐页复制与旧页开销 | 新搬迁只复制可达页和捕获的增量，多个页同批写入。仍可续跑旧版已经开始的复制操作。 |
| 续页、失败重试及退役清理 | 游标按租约滑动续期，只读 POST 可以重试，成功的不可变根读取省去数据组 ReadBarrier。历史索引按明确前缀清理，保留管理定义和任务记录。损坏与布局切换分别返回非重试 500、可重试 409。 |

同一份合成的 4 万实体、两数据组样本记录分片读取调用次数。它经过实际分区树、查询器及批次预算，调用在进程内完成。

| 查询 | `61a3bca` | 修复后 |
| --- | ---: | ---: |
| 前 100 条 | 357 | 12 |
| 前 1000 条 | 1257 | 40 |
| 无 kind、排序后取 1000 条 | 2048，预算耗尽 | 1509，返回 1000 条 |
