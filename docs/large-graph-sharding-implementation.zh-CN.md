# 大图分片实施说明

2026-11-09，基于 `28bb6df` 的开发分支 `codex/large-graph-sharding`。完整目标见[设计](large-graph-sharding-design.zh-CN.md)。读路径优化与当前局部测量见[第一轮优化记录](large-graph-sharding-optimization-2026-11-09.zh-CN.md)。本说明描述已写入代码的范围，不代表 2.4.4 已发布能力或跨主机容量资格。

## 已实现路径

- 租户仍是一张图；目录定位 home group，图控制状态管理 256 个 SHA-256 虚拟分区。普通租户保持原路径。
- 数据采用有校验和的不可变分页树；更新只改受影响路径。实体、边主记录、正反邻接、别名、全局身份/unique/关系基数目录和兼容逻辑摘要分别保存。提交校验只加载有界依赖闭包。
- 图控制组串行决定事务，输入分块多数派落盘，最多四个并发准备 RPC，全部准备成功后原子发布统一版本和根向量，再完成参与者收尾。幂等请求保留原结果；结果未知不盲目重放。完成后删除受理输入并缩小收据。
- 实体点查、基于轻量 ID/类型目录的全局有序实体扫描、结构化查询及查询 NDJSON；包括正向、反向和双向邻接、现有 lazy 引擎支持的遍历、路径、排序和聚合。无法执行的查询返回明确错误，不加载整图兜底。
- `min_version` 的 JSON、请求头和 URL 解析复用原 API；固定根的持久化分页 pin 绑定租户、generation、版本和查询，跨写入及搬迁保持版本，到期明确失效。
- 旧租户按维护窗口流式转换，保留原版本、内容摘要、记录时间及旧 direct-commit 幂等结果。转换前要求当前版本的分页索引和摘要，缺少时在改变目录状态前拒绝。成功后分批清理旧图、索引和原请求正文，保留租户管理元数据。
- 在线分区搬迁：先复制旧页并持久化捕获新增页，再阻止新图事务、复制最终增量、隔离源、验证并安装目标根、切换 epoch 和布局 revision。搬迁不改变图版本或 `data_hash`。切换前可取消并提升源 epoch；切换后只向前恢复。源副本等待最长查询期限后分批退役。
- GC 保护当前根、有效 pin 和准备事务；短暂停写以安装各分区保护边界，随后边写边标记和回收。新准备产生的页在同一复制事务内加入保护集合。GC 与迁移互斥，支持手动触发及租户 GC 周期；协调状态和临时标记均可恢复。
- Raft 捕获及安装快照同时验证分区根、准备根、受理输入、分页、迁移增量和 GC 引用。验证针对暂存视图，失败不会替换原目录。

## 管理接口

管理请求使用 router 的 Bearer 令牌。目录组、home group 和所有目标数据组均须完成协议 5 升级，每个数据组至少三个独立副本。以下示例仅展示请求格式，地址和组 ID 按部署填写。

```http
POST /v1/cluster/graphs
Authorization: Bearer <operator-token>
Content-Type: application/json

{"tenant_id":"big","data_groups":["data-a","data-b"]}
```

租户须已存在，目标数据组数量为 2–256。非空旧图先通过现有 `POST /v1/indexes/rebuild` 准备当前版本的分页索引，必要时先 compact 旧单体快照。接口返回 `202` 后通过下列接口查看转换阶段或图描述；错误写在 `partition_error`，后台按持久化位置重试。

```http
GET /v1/cluster/graphs/big

POST /v1/cluster/graphs/big/partitions/42/move
Content-Type: application/json

{"target_group":"data-c"}

GET /v1/cluster/graphs/big/partitions/42/move

POST /v1/cluster/graphs/big/partitions/42/cancel
Content-Type: application/json

{"move_id":"<id-from-status>"}

POST /v1/cluster/graphs/big/gc
GET /v1/cluster/graphs/big/gc
```

新增目标组先使用现有分片注册接口注册。搬迁和 GC 返回 `202`，进度随图控制状态复制。相同搬迁目标或正在运行的 GC 会返回已有操作。每图只运行一个搬迁；搬迁的 `cleanup` 阶段保护进行中的旧位置读取，结束前不能开始下一次搬迁。

## 当前预算

| 边界 | 当前实现 |
| --- | --- |
| 虚拟分区 | 固定 256，初始均匀分配到指定组 |
| 单个实体、边或目录值 | 1 MiB |
| 单次请求正文 | 8 MiB；不拆散原子提交 |
| 分区变更 | 最多 4096 行、8 MiB |
| 变更依赖闭包 | 最多 8192 个实体/边、64 MiB、32 轮；读取另受 RPC/字节预算约束 |
| 查询 | 最多 2048 个分区读取 RPC、64 MiB 返回数据、2 分钟；复用引擎访问数量等限制 |
| 同一 router/client 上的图请求 | 最多 8 个并发，超出返回 429 |
| 单次分区读取 | 最多 128 个 key，或 256 行扫描；返回数据上限 4 MiB。多 key 请求内解码页缓存按估算另限制为 4 MiB、128 页 |
| 分页 pin | 每图最多 4096；游标 5 分钟，另保护 2 分钟的进行中查询 |
| 搬迁 | 每次最多 4 个不可变页、4 MiB，保留持久化游标与增量根 |
| GC | 每步有界标记、扫描及删除；删除数据有 8 MiB 批次预算 |

当前每个图查询及实体点查都通过控制组持久化 pin，非分页请求结束后释放；因此读取也会产生控制组日志与多数派往返，尚未优化为可复用的读租约。

这些是保护上限，不是已验收的大图容量参数。来源全量清理、超大级联删除等操作可能超出提交闭包预算，需要后续维护任务。逻辑摘要维持 `sha256-shards-v2`；单叶更新仍可能重算该逻辑桶，不能视为恒定成本。

## 尚未实现及使用边界

当前分片模式只开放上述数据路径。WAL/批量 ingest/import、GQL/GraphQL、边扫描/导出、跨组备份恢复/clone、完整租户生命周期、配置写入及带存量数据的 schema 修改尚未接入；不支持的接口返回 `501 operation_disabled`，不能落到已退役的旧单组数据。当前仅有 Raft 副本快照恢复，不等于整图跨组备份恢复。

转换发布前的取消接口、失效受理前暂存块清理、幂等收据保留策略、超级节点 segment、hash 范围继续拆分、home group 搬迁和已用数据组的自动排空尚未完成。目录保守保留图关联，注销曾关联的组可能仍被拒绝。转换已进入初始化后应排除错误并继续，不得手工删描述或改目录强行恢复旧模式。

因此本分支用于开发和资格验证；设计第 4 阶段尚未全部完成，第 5 阶段未实现。不能在仍依赖上述接口的生产租户上直接切换。三副本需要独立故障域；三台机器三副本不会增加基础可用容量。

## 运行验证

运行环境：OrbStack Linux arm64，`golang:1.27.3-bookworm`，使用仓库已有依赖，没有新增运行依赖。九个真实 Raft 节点组成一个三副本目录组及两个三副本数据组，各副本独立目录，通过 HTTP 复制。节点运行在同一 Go 测试进程，测试逐节点关闭和重建；这不等价于九个独立服务进程或跨主机验收。

已通过的行为包括跨组边和反向查询、全局 unique/关系基数、级联删除、与单组相同逻辑摘要、准备/决定响应丢失、统一版本分页与到期、旧图转换及旧请求重试、搬迁中写入与取消、搬迁和 GC 期间控制 Leader 替换、回收期间的准备写入及 pin 保护、缺输入/缺准备页的快照拒绝，以及捕获快照安装到独立目录。

测试入口为 `internal/partition` 及 `internal/ha/partition_test.go`。全仓库、race 和静态检查结果见下表；本页不将这些检查写成完整发布门禁。尚未验证真实多主机容量、超过单机内存的图、分片备份恢复、双版本协议 5 滚动、磁盘满及完整故障矩阵，未测量线性扩展收益。
