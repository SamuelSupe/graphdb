# 产品 P0/P1 完整运行状态恢复审核

本轮以独立工作树 `codex/raft-ha` 的 `3e5252ad6eb424c3db9dfd8233215e79fd30ed25` 为基线，复核单机/WAL、Raft 持久化与退出、完整运行状态备份/恢复及分片路由边界。未复现新增 P0，确认并修复两项 P1。这是尚未发布的本地候选，不代表已经证明全产品没有其他缺陷。

| 问题 | 实际复现 | 修复 |
| --- | --- | --- |
| P1：恢复时不同角色映射到同一目标子目录 | 用分离的 data 与 WAL/Raft 根目录生成合法归档，再把目标辅助根目录放到 data 内。归档中两个不同角色的 `state` 最后映射到同一物理文件；命令成功，但后发布的文件覆盖先发布的文件。 | 在归档预检中核对实际目标路径。父角色的对象不能进入另一个角色的嵌套根目录，即使该角色没有同名对象；冲突在目标目录创建前拒绝。默认嵌套布局继续可用。同文件系统暂存文件以硬链接发布，目标已有文件时失败，不覆盖意外出现的文件。 |
| P1：离线恢复未取得独立 WAL/Raft 的占用锁 | 使用真实 WAL 或 bbolt 持有辅助目录，而 data 根目录空闲。旧备份命令仍成功；模拟同一归档的中断恢复后，旧恢复命令删除并替换活动日志/数据库，WAL 的后续 durable 确认和数据库的后续提交在重开后丢失。 | 备份和恢复全程持有全部配置角色的锁，先取得锁再清理旧恢复文件。复用 WAL `.lock`，Raft 节点新增同类目录锁并随存储生命周期释放。恢复同时锁定已有和暂存的新 `raft.db` inode，以保护只锁数据库的旧程序。进程锁对象不再归档或发布；旧归档及恢复日志中的 WAL `.lock` 兼容读取，保留目标 inode。 |

## 回归证据

`TestRuntimeRecoveryRejectsCrossRoleDestinations` 对 WAL 与 Raft 分别执行真实备份和恢复，验证冲突布局拒绝且目标尚未创建；改用不交叠的目标后，两份不同内容均完整保留。

`TestRuntimeRecoveryRejectsLiveAuxiliaryDirectory` 使用真实 `OpenIngestWAL` 与 `bolt.Open`，分别验证活动辅助目录阻止备份，失败备份不发布归档；所有者退出后备份正常。随后创建与归档匹配的恢复日志，保持辅助目录运行并写入新确认状态。恢复续跑必须拒绝，重开后 WAL 记录与数据库提交仍存在。修复前四种备份/恢复场景均失败，见 `runtime-before-final.log`。

扩展原有完整恢复测试，按旧格式写入 WAL `.lock`，恢复 pending 受理身份、committed 幂等结果、查询模板及图；旧恢复日志也包含锁对象。中断续跑必须保留锁 inode，拒绝未知对象，并继续恢复。该测试同时保留坏归档拒绝与在线目录备份拒绝场景。

Raft 包曾出现 `snapshot_metadata` 等待超时。日志显示 follower 已通过排队的追加消息提交到快照位置，因而正常忽略同位置快照；这不是新的生产 P1。测试现在等待已进入的 HTTP handler 退出，并把追加消息隔离到快照持久化之后，明确保护原有“先恢复快照，再保留后续成员元数据”的回归边界。专项连续五次通过；中间失败日志保留，不能计作最终通过。

## 使用与资格边界

使用同一份配置保存 data、WAL、Raft 根目录及节点身份。完整恢复仍是离线文件归档，必须停止所有会使用这些角色目录的服务；文件锁保护受支持的写入入口，不保护手工删文件、绕过锁的外部程序或不提供本地锁语义的网络文件系统。不要删除 `.lock`、`.graphdb.lock` 或数据库来解除占用。目标子目录冲突时选择无对象交叠的布局，不改写归档身份绕过检查。

归档格式及 Raft 协议编号不变，旧归档的锁对象只参与输入校验，不参与恢复文件计划或发布；旧恢复日志中对应对象也会剔除后再核对文件计划。独立 Raft 目录锁不改变已有数据文件格式。旧程序只有数据库锁，新恢复命令会同时取得该锁；原始归档与恢复日志应保留到确认恢复成功。

完整集群灾备仍需要在一致停机边界保存所有节点和拓扑，再在隔离环境恢复足够组成多数派的成员。单节点归档不构成集群一致性备份；文件传输校验不代替图/WAL/Raft 语义审计。本轮不新增吞吐或容量承诺，也不修复已经被旧恢复覆盖的日志。此前来源身份的维护升级限制及旧进行中迁移的处置要求继续适用。

跨宿主机按用户决定继续待验收。新的双版本混部矩阵、真实坏盘、生产容量、日级负载、30 分钟 soak 和新的 S3/MinIO 验收本轮未运行。操作步骤与错误处置见[产品运维](product-operations.zh-CN.md#完整运行状态灾备)、[Raft 运维](raft-operations.zh-CN.md)和[诊断指标](diagnostics-metrics.zh-CN.md)。
