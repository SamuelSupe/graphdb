# 故障隔离与迁移验证：2026-10-02

本轮在独立 worktree `GraphDB-raft-ha`、分支 `codex/raft-ha` 实现维护队列公平推进、目录故障隔离、磁盘分块迁移和协议 3 GC 准备/发布分离。单机 direct/WAL、单组 Raft 和租户分片继续同时支持。本记录属于本机候选验收，不代表正式发行或跨宿主机资格。

## 改动及边界

| 问题 | 实现 | 保留边界 |
| --- | --- | --- |
| 首个 compact 被磁盘准入阻塞，其他租户 GC 无法推进 | 维护扫描不占应用屏障，跳过被阻塞任务，按租户/任务位置循环推进 | 仍为单个维护 worker；GC 也需要实际可用磁盘 |
| 目录失联后所有 router 被 readiness 摘流 | 强一致定位所得的已知 active 路由可保留 5 分钟；目录探测限时并退避 | 未知租户、目录管理及过期缓存不可用；数据组始终执行 epoch 隔离及多数派屏障 |
| 每个迁移轮次全量导出，三端持有完整载荷 | 源固定文件视图、导出落盘并缓存，协调器按目标持久化位置读取最多 8 个 1MiB 块；目标逐对象暂存 | 租户迁移仍冻结读写；单对象、图解码及事务回滚仍需要内存；旧源接口回退仍全量缓冲 |
| GC 扫描与准备占全组应用屏障 | 协议 3 从固定租户视图准备文件及删除清单，经多数派复制后核验并发布 | 最终发布和删除仍使用屏障；repair、导入、图恢复尚未拆分 |
| 维护发布阻塞磁盘健康检查，全部副本被网关摘流 | 文件探测仅持目录生命周期引用，独立临时文件执行实际写入和同步 | 关闭、恢复失败及真实 IO 错误仍拒绝；图读取仍等待应用完成 |
| 持续写入导致维护准备反复失效，同步回退阻塞整组 | 三次冲突后暂停该租户新变更并排空已受理 WAL，继续在屏障外准备和复制 | 该租户短暂返回可重试 429；最终发布仍有共享屏障 |
| 每次位置查询解析完整 catalog JSON | 提交成功后发布不可变内存状态，变更复制 map 和受影响的 move | 目录变更仍重写完整 JSON，尚未按租户拆分存储 |
| 大量维护对象逐文件持久化回滚日志，应用阻塞超过一分钟 | 修改前按最多 64 个对象/约 16MiB 分批持久化原始内容 | 最终发布仍使用共享屏障，单个大对象及完整回滚仍需内存 |
| 一次就绪超时立即摘流，短暂 IO 长尾同时移除全部副本 | 两种 HAProxy 示例要求连续三次失败；升级控制器摘流后默认等 7 秒 | 摘流更慢；数据请求始终要求多数派及应用屏障 |

维护准备连续三次冲突后，当前 Leader 暂停该租户的新变更，先排空已受理 WAL，再在应用屏障外准备并复制结果。暂停期间该租户的新变更返回带重试提示的 `429 maintenance_pending`；读取、任务入队/取消/重试与其他租户继续服务。取消或换主会中止准备并恢复准入。记录 `maintenance_write_pause/maintenance_write_deferred` 及本地 `graphdb_ha_maintenance_writes_paused`，结束或取消后恢复准入，换主/重启重新计数。源导出和目标暂存复用已保留的 `.snapshot-view-*` 临时目录并写入创建标记；进程强杀后，下次取得目录独占锁并核对标记后清理残留，不能清理其他仍持锁进程的活跃文件。

新迁移接口保留原 JSON 字节格式、摘要和既有复制安装命令；旧源无新接口时自动回退。协议 1/2 继续采用原 GC 语义，协议 3 GC 使用维护归档格式 2。首个协议 3 提案要求全部投票副本声明支持；协议最低要求持久化，不能改回环境变量后用最高协议为 2 的旧程序打开原目录。

新增 router 保留路由数、目录故障观察及最后成功时间，维护跳过/选择事件、迁移导出构建耗时和块读取事件；告警示例共 20 条。指标不在采集时请求目录或多数派。readiness 表示入口有能力服务已知路由，不能当作全组健康证明。

## 未验证及后续工作

跨宿主机按用户决定保留待验收。大容量、大租户、天级稳定性、生产认证/TLS 接入和告警实际通知尚未运行；本机 30 分钟负载不能替代这些资格。没有同环境 A/A 性能校准和前后对照，因此本轮不报告吞吐提升百分比或容量上限。维护期间仍有明确的写入 429 与十秒级长尾，最终通过不代表满足低延迟生产 SLO。

在线完整运行态备份、增量备份/PITR、租户内部图分区、按流量/容量自动均衡，以及目录逐租户存储仍未实现。现有完整运行态灾备仍要求一致的离线边界。正式发布、版本 tag、远端 CI 和发行资产本轮未执行。

前一候选 `2.1.2-raft-isolation1` 的持续负载发现索引重建因持续写入反复失效，超过 10 分钟期限；该候选的 soak 判为 FAIL，并在确认后停止，证据保留于 `/tmp/graphdb-isolation-20261002`。当时加入三次冲突后的同步回退；第四候选负载证据又发现该回退的全组阻塞问题，第五候选已替换为单租户准入暂停，集成用例同时持续写入维护租户及另一租户，不能沿用前一二进制的门禁结果。

第二候选 `2.1.2-raft-isolation2` 全量及混部滚动通过，稳定性负载因收紧启动清理范围而主动中止，记为 NOT COMPLETED；没有把这次中止当作通过。最终兼容门禁一次因本机端口占用未能启动，换独立端口范围后 `compatibility-final/` 完整通过；启动失败记录保留。

第三候选首次 soak 与其他门禁并行出现 503/504，GC 状态查询失败；在全部测试结束后，同二进制于 `protocol3-final/` 独立重验，首次 compact 附近仍出现网关 503。两次均为 FAIL。故障时三个副本仍有同一 Leader、多数派活跃且没有持久化错误；真实原因是磁盘健康探测等待全目录发布屏障，被网关判断为全部副本不可用。第四候选将独立探测移出该屏障，保留生命周期和恢复错误检查；新增回归验证占用发布屏障时仍能探测，以及恢复失败和目录关闭仍拒绝。持续负载重验维持原超时、快照阈值和错误标准。

第四候选 `2.1.2-raft-isolation4` 的完整测试、探测并发回归、实际恢复/压力/滚动重启均通过，但独立 soak 在索引重建附近仍出现转发 504，判为 FAIL，证据保留于 `/tmp/graphdb-isolation4-20261002`。原因是同步回退将重型维护再次放进全组应用屏障。第五候选以单租户准入暂停与 WAL 排空替代同步回退，没有修改客户端超时、快照频率或错误标准。既有 soak 已允许写入 429 背压；最终报告会保留这类暂停次数，不能把它算成持续不受阻写入。

第五候选全量测试及关键并发检测通过；实际恢复、磁盘压力和滚动重启通过。持续负载早期发现准入暂停需要放行任务取消，主动停止并标为 NOT COMPLETED。第六候选放行取消，并以本地周期检查中止已取消或失去领导权的准备工作；新增回归同时验证取消信号及恢复写入。

第六候选 30 分钟负载判为 FAIL，保留 `/tmp/graphdb-isolation6-20261002`。磁盘探测无失败，网关曾在选主期间同时收到三个副本的 503；记录中存在超过一秒的 Ready 持久化耗时，尚未证明此次摘流只有一个原因。审查确认现有传输把心跳和慢日志追加/快照串在同一发送队列，回归可稳定复现该阻塞导致 ReadIndex 失败；另有维护暂停误拒绝后续任务入队。第七候选为控制消息分配独立有界队列，继续保留磁盘同步和原选举时序；任务仅入队/取消/重试可绕过数据写入暂停，执行仍由串行 worker 完成。新增真实三节点用例阻塞两个 Follower 的追加 HTTP 传输超过选举期限，核对 ReadIndex 仍成功、term 不变以及解除阻塞后原写入完成；原暂停用例增加 GC 和索引任务的受理断言。第七候选随后运行到第二轮维护出现错误并停止，记为 FAIL，不能沿用第六候选的短测结果。

第七候选第二轮维护期间仍出现多数派摘流：term 从 7 变为 9，三个副本均记录 1–2.5 秒 Ready 持久化长尾，网关收到快速 503，未观察到 quorum_barrier 超时。记录 162 次查询/写入错误后主动停止，结果为 FAIL，证据保留于 `/tmp/graphdb-isolation7-20261002`。第八候选将选举等待独立配置为 30 个 tick，心跳保持 100ms，默认随机选举约 3–6 秒；这是程序默认行为的调整，不是只放宽测试夹具。保留原客户端期限、快照阈值及错误判定。代价是异常失主检测更慢，需要重新验证接管时间；新增实际时序诊断指标。现有单元夹具显式保留 10 个 tick，实际部署使用新默认值。

第八候选最初目标并发测试发现取消场景未固定排队前置条件：后台可能先完成任务，此时取消 API 正确保留 succeeded，测试却要求 canceled。未观察到 DATA RACE。已用现有维护锁阻止后台执行该测试任务，保留 WAL 排空、背压、入队、取消与恢复断言；`/tmp/graphdb-isolation8-20261002/targeted-race-fixed.log` 通过。修正后的相关 HA 行为已通过目标并发重验；第八候选该次普通全量测试的生产源码一致，该用例编译时仍使用此前夹具。当前候选的全量测试已包含修正后的夹具。

第八候选保持 term=7，但维护发布的一次 apply 超过 60 秒，产生 15 次错误事件，其中 2 次写入 504。多数派确认仍快速，ReadBarrier 等待应用完成导致转发超时。确认失败后主动停止，结果为 FAIL；不是完整 30 分钟通过，后续分片门禁未执行。证据保留于 `/tmp/graphdb-isolation8-20261002`。第九候选在准备维护修改前按有界批次持久化全部 before-image，保留最终文件、目录和提交标记；既有进程中断用例扩展到多个批次、部分改写/删除/新建，以及尚未修改的对象，核对完整回滚与原 checkpoint。

第九候选的初次持续负载在首轮 GC 完成后出现 46 次 503 错误，确认后主动停止，`protocol3/` 记为 FAIL。三个副本 term 均为 7，GC、索引重建和多轮压缩已完成，应用记录均在 10 秒内。网关日志显示一次约两秒的就绪失败会立即摘流，随后几十毫秒的检查恢复成功；原部署的 `fall 1` 使同机 IO 长尾同时移除全部后端。最终保持同一二进制、就绪期限、快照阈值和负载错误标准，修改实际部署策略为连续三次失败才摘流，升级副本及 router 的默认传播等待均为 7 秒。最终部署的 `protocol3-final/` 已独立完整重验通过，结果来自完整门禁及 30 分钟负载。
