# 产品可靠性与运维完善

基线为 `5b01a1f9`。默认单机、单组 Raft、租户分片同时保留。按以下顺序实施和验证，跨宿主机仍待验收。

1. 磁盘保护：用实际文件系统可用空间限制新受理，维护、恢复和迁移在构建前估算额外空间。保留已受理 WAL 和控制记录的排空空间，GC、读取和诊断仍可用。磁盘状态属于本地资源，不能作为各副本应用同一日志时的业务判定。
2. 快照与维护：将完整快照压缩、传输移出全量内存缓冲；固定一致性位置和成员元数据，校验后原子安装。新编码需要明确的兼容边界与真实混部验证，不能直接沿用旧版本资格。
3. 灾备：明确区分图数据备份和完整运行状态备份，恢复保存查询、接入身份及采集状态，并处理已受理但未发布的工作；保留历史图备份读取。用实际恢复与同身份重试验证业务续跑。
4. 维护隔离：把耗时准备与最终原子发布分开，发布时核对版本、租户代次及归属；减少共享应用屏障被准备阶段阻塞。验证其他租户持续读写，避免将更长超时当成延迟优化。
5. 运维交付：提供统一本地诊断、磁盘/复制/任务告警、受保护的生产部署示例和操作流程，统一单机与 Raft 的能力文档。

单租户图切分、历史图查询、复杂查询语言属于独立能力设计，本轮先落实上述明确建议。没有生产容量或任意旧/新版本兼容承诺。验证按阶段集中执行，最后进行同二进制的单机/Raft/分片部署回归。
