# 产品 P0/P1 复制与快照后续审核

本轮以独立工作树 `codex/raft-ha` 的 `926cac73c2094b5b46c1498c2ee10b8e6afd2ea3` 为基线，继续复核单机/WAL、复制事务、迁移受理/安装、快照捕获/恢复和目录角色/前缀保护等边界，重点检查已确认数据在后续复制阶段的完整性。未复现新增 P0，确认并修复三项 P1；本轮是本地候选，不是正式发布，不代表已证明全产品没有其他缺陷。

## 回归证据

`TestHAShardPersistedChunkFailureStopsReplicaUntilReplay` 使用三个真实 Raft 节点和独立目录，分别覆盖丢失块及同长度字节变化：故障副本停止且保留安装前 checkpoint，健康多数派安装、激活并继续写入；恢复正确块并重开后，安装及后续日志重放，源实体和新写入实体都存在。修复前两种情况均失败，见 `chunk-before.log`。

扩展现有三副本输入拒绝场景，检查传输整体摘要错误、安装大小错误、未完整受理以及旧进行中分块缺少绑定都返回 409，各副本继续应用且代次/清理标记不变，之后正常写入成功；原有缺失提交、坏 manifest/索引拒绝场景继续覆盖。旧源导出格式回退、丢失响应后的幂等 stage/install、分片换主、取消和迁回由原有集成与部署门禁保护。

`TestApplicationSnapshotRejectsCorruptPublishedGraph` 使用实际 Application 和 FileStore 的两套快照接口，覆盖缺失 head、缺失 commit、不可解码 commit；输入来自原始对象快照编码器，字节校验正确。接收端必须保留旧图、实体和 checkpoint。还检查健康捕获视图在 live 文件随后被 unlink 后仍可编码，并恢复出原完整图，避免错误地校验另一个时刻的 live 目录。源端失败证据见 `snapshot-before.log`；先修源端但尚未修接收端时，六个接收场景仍破坏目标，见 `restore-before.log`。

`TestHARejectsChangedDataPrefixOnRestart` 覆盖已有绑定和旧目录无绑定两种重启边界，错误配置不得启动或改动图及 checkpoint；恢复原前缀重开后，原实体和后续复制写入都可读取。`TestApplicationRejectsForeignDataPrefix` 在新旧接收入口送入另一前缀的合法对象归档，并在真实应用入口提交带错误前缀的新命令，要求旧图和 checkpoint 保持不变。修复前前缀重启与两种快照接收均失败，见 `prefix-before.log`；该日志的新命令场景用于验证新增约束，旧版本本来没有前缀字段。

## 使用与资格边界

升级前完成迁移，或在目录切换前取消旧迁移；目标投票组混部期间暂停新迁移，全部升级后再发起。旧 importing 状态没有分块摘要，返回 409 后按既有取消流程重新传输，不能修改归属记录或强制推进切换；已经切换目录的迁移不允许取消，应先完成原流程。旧来源的完整导出格式仍可被新目标重新分块受理。本轮没有增加协议编号或改变快照归档编码，但改变了受影响输入的执行语义，没有新的双版本混部资格。

同组所有节点保持原 `GRAPHDB_PREFIX`；旧日志缺少新字段仍兼容读取，旧二进制混部期间不具备新增约束。前缀绑定保护正常配置变更及快照命名空间，不承担人为删除/篡改身份文件后的完整溯源。旧目录首次绑定会扫描业务对象键，图快照本来就捕获整个专用数据目录；包含多个业务前缀的 Raft 目录会被拒绝，不能作为共享目录使用。

图校验会增加快照构建/恢复的时间和图加载内存，分块摘要也增加受理的散列与归属记录成本，本轮没有吞吐或容量提升声明。空或旧算法 `data_hash` 保持原兼容读取语义，没有额外的当前算法绑定保证；没有对每次请求、所有控制文件或任意物理损坏作完整性证明，也不能识别整份目录被替换为另一份自洽数据。源码中的通用对象快照保留原始存储语义，实际 Raft Application 为源端和接收端统一指定租户前缀。

跨宿主机按用户决定继续待验收。真实坏盘、生产容量、长时间负载、新的混部矩阵和新的 S3/MinIO 门禁本轮未运行。此前来源身份的维护升级限制继续适用；旧程序已经消费的迁移分歧、已安装的损坏快照或已清理的源文件不会被自动恢复。处置见[Raft 运维](raft-operations.zh-CN.md)、[分片](sharding.zh-CN.md)和[诊断指标](diagnostics-metrics.zh-CN.md)。
