# 架构收尾与 S3 备份自动化验证

日期：2026-09-28。工作区：`/Users/livesite/Documents/GraphDB`。
在前一阶段架构精简的未提交改动上继续实施；未提交、推送或发布。

## 实现范围

1. **单进程协调**：生产路径和内存测试实现都使用本地任务注册表。删除不再生效的租约 TTL、任务标记 TTL、旧索引运行标记查询及 GC 心跳协调；持久化 writer token/epoch、条件写和租户代次隔离保留。
2. **统一退出**：普通任务、增量索引、缓存维护及维护调度登记到同一退出边界，WAL 关闭错误返回调用者，最后释放目录独占锁。后台退出超时保留目录锁。HTTP 优雅退出超时后关闭活动连接，取消请求并释放读视图。
3. **缓存发布**：读缓存共用存储层的租户代次，提交、WAL、恢复和删除通过同一发布/失效机制更新。周期循环只处理空闲淘汰；读写缓存复用不可变图，仍保留各自的容量预算。
4. **提交收尾**：Direct 与 WAL 共用 durable manifest 发布、失败缓存处理及新图发布入口；受理、文件持久化顺序、幂等和终态协议保留。
5. **GC 并发**：GC 不再为删除取得租户读视图排他权。旧视图所需文件按进入代次延迟回收，新查询继续进入；同版本 catalog 重新引用旧文件也受到保护。扫描/字节/时间预算及租户锁保留；恢复、清空和显式 recovery/commit cleanup 仍为排他生命周期操作。
6. **S3 自动化**：租户间隔调度、持久化计划 ID、重启检查、指数退避、完整下载校验、可选恢复演练、数量/期限保留策略、可恢复删除检查点及状态/显式重置 API，全部复用现有任务队列。

自动备份只在配置启用后执行。每轮成功后回收本地捕获文件，失败保留重试输入；演练目录在正常结束时移除，异常退出遗留由既有启动恢复清理。启用演练时复用恢复下载的完整性校验，避免重复下载；恢复完成即归还维护执行名额，再处理远端保留清理。

远端清理仅作用于自动备份，保留最新和本轮已校验快照，并保护本进程正在读取的备份。手动快照不自动删除。每轮最多删除 100 份；不同实例须使用独立的可写清理前缀。

配置、权限、状态接口、SDK 和运维边界见[备份自动化指南](object-backup.zh-CN.md#自动备份)。

### 重点回归

- 后台工作尚未退出时，第二个进程不能重新打开目录；完成退出后可以打开。
- 增量索引在阻塞写入时取消退出，已发布的图写入保持可读。
- GC 保留旧查询所需文件；新查询不阻止已经过期的旧文件回收；同版本索引目录重新引用旧文件不会绕过保护。
- 阶段恢复/恢复演练的内部同步任务登记为活动执行者，不会被本地恢复检查误判为已退出。
- 收尾测试曾复现“dry-run 已显示完成，随后的正式恢复仍被旧任务拒绝”。原因是终态文件先于内存准入表更新；任务查询现同步已确认的终态。确定性测试模拟该窗口，覆盖普通任务和统一索引任务，修复后重复 race 通过。
- S3 发布失败不可见、分片取消清理、校验损坏内容、重启后重试复用原捕获版本。
- 自动轮次重启恢复、退避和成功观察；保留清理保护手动备份及正在读取的对象，删除清单后中断可继续删除 payload。
- 自动演练确实完成恢复和审计；关闭策略、重置状态及调度状态跨 HTTP 服务重启保留。
- HTTP 验证发现并修复新接口空审计字段导致的 panic；缺少 S3 配置时维护循环报告错误并继续运行。
