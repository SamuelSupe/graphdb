# 本地磁盘版：第四轮 P1 修复

日期：2026-09-16。工作区 `/Users/livesite/Documents/GraphDB-local-disk-v2`，分支 `codex/local-disk-v2`。

修复第四轮审查确认的两类 P1。保留已有本地磁盘、对象备份及前三轮改动；没有提交、推送或合并。

## 修复结果

### 1. 租户创建与克隆完整发布

独占本地运行时中，创建和克隆在同一文件系统的暂存目录构建完整 manifest、元数据、配置、来源策略和关系约束，再复用恢复已有的持久化日志与目录切换机制。构建失败不会把半成品租户暴露为 active；未发布暂存目录在退出或重新打开时清理，随后可重新执行原操作。

- 创建前先校验配置和来源策略。
- 生命周期操作依次暂停 WAL 受理、排空已受理请求、取得排他读视图及租户锁。
- 保留对已有 legacy 租户的管理和软删除后重新创建语义。未改写的文件在发布前从在线目录建立硬链接，保留原图、幂等记录及构建期间完成的任务写入。
- 构建不占用全局目录访问锁；合并保留文件和切换时才取得该锁。切换后失效图、配置和索引相关缓存。
- 目录切换仍是带恢复日志的多步操作，不把多个 rename 称作原子事务。未提交的切换按已有恢复机制回退；无法完成回退时继续拒绝写入，要求重新打开目录。

内存测试存储和隔离暂存存储继续使用原有构建函数，避免重复实现克隆内容。实际服务和离线 CLI 的独占文件存储使用完整发布路径。

### 2. 幂等请求的终态恢复与 compact 保护

确认 prepared 请求已发布后，先持久化 committed 再返回重放成功。compact 在丢弃提交引用前处理被快照覆盖的 prepared 记录：

- 已发布：补写 committed。
- 明确未发布，且该版本属于其他提交：持久化回 pending，保留后续合法重试能力。
- 无法确定，或终态写入失败：停止 compact 的 manifest 发布，保留原提交证据。

原写入者在租户锁外完成终态时，允许其他重试或 compact 已完成同一请求；CAS 冲突后只在请求和提交结果身份一致且记录确为 committed 时视为成功。

同时处理无变化请求，包括 v0；这类请求不需要证明图发布。修正 pending 记录的结果租户标识，并校验兼容旧 pending 记录采用空结果租户参与哈希的表示。未取消持久化内容哈希校验，也未改变 Parquet/WAL 公开布局。

## 实际验证

环境：OrbStack / Linux 本地验证卷，Go 1.25。单元及 race 容器限制 4 CPU / 6 GiB；HTTP 门禁使用 2 CPU / 4 GiB。未停止无关工作负载。

| 验证 | 结果 |
| --- | --- |
| `go test -mod=readonly ./...` | 最终源码全部通过，包含 Go SDK |
| `go vet -mod=readonly ./...` | 通过 |
| storage/httpapi 定向 `-race` | 67 个顶层测试通过，无数据竞争报告 |
| direct/WAL 真实 HTTP 门禁 | 通过：图查询、租户生命周期、任务、备份恢复、导出、compact/GC、4 写入与 16 查询客户端、重启前后快照一致 |
| Python SDK 真实 HTTP 检查 | 12 项通过 |
| 审查期间源码一致性 | 最终源码与验证快照比较一致 |

新增/扩展的行为回归覆盖：

1. 创建和克隆在配置、元数据及注册表阶段失败；在线目标没有半成品数据，重新打开后重试完成，配置、来源策略和实体配额生效。
2. 管理已有 legacy 租户时保留图、既有幂等结果及暂存期间完成的任务。
3. 普通和无变化请求在“先重试再 compact”及“先 compact 再重试”两种顺序下，经历 GC、关闭和重启后仍能重放原结果。
4. compact 的幂等终态补写失败时不发布快照 manifest；随后重试成功。
5. 原请求明确未发布时，compact 后仍允许提交该请求，且不虚报幂等成功。
6. 原写入者终态被阻塞时，另一写入与 compact 可完成，原写入者随后正常结束。
7. 当前及旧格式的 pending 记录可继续执行。

原审查的配置故障发生在在线目录。本轮配置已移入暂存目录，因此初始化回归在真实暂存构建函数中注入对应故障；注册表故障仍从公开 CreateTenant/CloneTenant 入口注入。

## 成本与边界

- compact 增加一次 direct 幂等记录扫描，按现有分页接口逐条处理；没有新增全历史记录集合。大量幂等历史下的维护耗时未做规模性能测量。
- 旧实现已经清理提交证据、且仍停留在 prepared 的记录，继续明确返回冲突；不会凭孤立文件存在或版本号猜测其已成功。此修复防止新的证据丢失，不对无法证明的旧结果进行自动补写。
- 未重跑独立 MinIO 对象备份门禁、旧版本二进制双向兼容门禁、性能对比、30 分钟持续负载或整机断电测试。共享的目录发布和本地备份恢复路径已通过本轮 unit/race/HTTP 验证。
