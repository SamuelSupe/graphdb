# 2026-10-03 完整测试与修复记录

本轮针对 `codex/raft-ha` 的未发布候选进行完整测试，单机与 Raft 两种模式都在范围内。起点为 `5fd0c9704ca573b902c66eaa1cbbffd2dc8c9b4a`；本轮整体结果为 **FAIL，尚未达到发布验收条件**。三个确认的 P1 已修复，本机完整测试通过；Linux 部署、持续负载及完整滚动矩阵仍有失败。本轮没有发布新版本。

## 已确认并修复的问题

1. **P1：编码路径绕过网关只读角色。** 实际 TLS 请求中，reader 的普通 `/v1/commits` 被拒绝，但 `/v1/%63ommits` 能写入。NGINX 改为使用规范化路径判定写角色，并在身份子请求之前保存原请求的方法和路径；覆盖客户端伪造的身份、方法和 URI 头。实际 TLS 的 17 项回归已经通过。CI、发行门禁及归档核验保存相同配置、客户端和身份测试服务的 SHA256。
2. **P1：非 UTC 类型时间造成持久化校验不一致。** JSON 内容摘要保留时区偏移，而 Parquet 列转为 UTC，导致确认写入、任务或保存查询在冷加载时校验失败。现在仅将结构化时间统一为 UTC，再计算持久化摘要；用户的不透明字段值保留原值，归一化不修改调用方的嵌套集合。回归覆盖提交、direct 幂等重试、WAL 记录、任务、实体页、边分片和冷重开。UTC 数据的格式与摘要不变。旧程序已产生的不一致对象继续拒绝，需要从可信备份或输入恢复，不能跳过校验；见[兼容性说明](naming-and-compatibility.zh-CN.md)。
3. **P1：写后校验读取失败导致任务丢失或 Raft 检查点错误前移。** 任务更新已发布后，租约或租户版本的一次 I/O 读取失败会删除对象；带租约路径还把错误转换成 CAS 冲突。Raft 的 HTTP 错误翻译可能将该失败响应与部分写入一并确认为已应用。现在仅在明确租约失效或租户删除、重建时清除晚到对象；临时读取失败保留发布对象并返回原始错误，原应用上下文记录错误，Raft 回滚整个应用且不推进检查点。两个回归的四个子场景在独立源码副本中替换回旧校验代码全部失败，新实现的本机与 Linux focused race 全部通过；原有删除、重建及晚到写入隔离回归也通过。
4. **测试基础设施修正。** 进程锁测试的子进程使用可阻塞的信号等待，避免 Go 检测到无事件的空等待后提前退出；磁盘压力测试在前置请求失败时也释放维护锁，避免清理死锁。维护并发测试保留实体数、协议、断言和请求预算，只减少与该行为无关的填充内容。滚动测试用网关就绪条件替代固定睡眠，不增加非幂等请求重试。S3 HTTP 验收的造数提交携带固定幂等键，只重试一秒自动维护周期触发的明确 `429/index_rebuild_running` 拒绝，不重试传输错误或其他失败。缓存刷新回归用显式过期替代十毫秒寿命与睡眠，保留刷新读取次数和新旧游标绑定断言，消除调度延迟造成的偶发多读。
5. **交付与文档修正。** 发行归档补齐 Raft 指标辅助脚本及 TLS 网关门禁。缺失的历史容量文件改为文字路径并注明证据不在当前树内，历史结果不能作为本候选的新验收。
