# GGraphDB 2.x 本地磁盘运行指南

[English](local-disk.md)

适用于 **GGraphDB 2.4.2**；发行资格见[版本验证](validation-v2.4.2.md)，升级约束见[版本边界](naming-and-compatibility.zh-CN.md)。

默认单机部署采用单进程、多租户并发读写。`GRAPHDB_DATA_DIR` 保存图数据、控制元数据、后台任务
及本地备份，运行时无需 PostgreSQL 或远端在线存储。可选的
[对象存储快照备份](object-backup.zh-CN.md) 用于本地磁盘丢失后的恢复。

本文描述本地存储与单机路径。同一发行程序还支持独立的 [Raft 副本](raft-ha.zh-CN.md) 和[租户分片](sharding.zh-CN.md)；复制持久化、管理、恢复及滚动升级须遵循对应契约。

2.3.4 起：数据根以上的父目录允许为符号链接，例如 macOS `/tmp` 和 Linux 挂载别名；数据根本身及内部受管理路径仍要求为真实目录。创建目录后仍同步其父目录，保留持久化屏障。

租户 ID 保留大小写。在不区分大小写的文件系统上，仅大小写不同的两个 ID 无法共存，2.3.10 起文件层按目录实际拼写拒绝别名，包括没有租户身份字段的 legacy 记录。文件系统大小写能力只检测一次；区分大小写的卷沿用原有查找路径。需要两者共存时使用区分大小写的卷。

2.3.4 起：普通 JSON 快照导出在不可变读取视图内逐条编码，不再复制整份 snapshot 或构建完整响应的 JSON 缓冲区，但仍需物化整图。大租户优先使用 NDJSON 快照接口，并确认最后的 `done:true`；缺少标记表示导出未完成。持续输出的流在每次批量 flush 时续期 10 分钟写入预算，不再按连接总时长限制为 10 分钟。

## 配置

| 配置 | 默认值与约束 |
| --- | --- |
| `GRAPHDB_DATA_DIR` | `.graphdb`，使用持久化本地目录 |
| `GRAPHDB_PREFIX` | `graphdb`，沿用现有租户目录布局；Raft 同组须一致，已绑定目录重启时不可更改，见[前缀保护](raft-operations.zh-CN.md) |
| `GRAPHDB_MODE` | 仅支持 `all` |
| `GRAPHDB_STORAGE` | 仅支持 `local` |
| `GRAPHDB_COORDINATION` | 仅支持 `local`，拒绝 PostgreSQL 配置 |
| `GRAPHDB_INGEST_MODE` | 默认 `direct`，可选 `wal` |
| `GRAPHDB_INGEST_WAL_DURABILITY` | 默认 `sync`，持久化确认前执行 fsync |
| `GRAPHDB_INGEST_WAL_DIR` | 默认 `<data-dir>/wal/ingest` |
| `GRAPHDB_READER_CACHE_MAX_BYTES` | 默认 512 MiB |
| `GRAPHDB_READER_CACHE_MAX_TENANTS` | 默认 64 |
| `GRAPHDB_INDEX_RANGE_PAGES` | 默认 `false`；所有读节点和副本升级后显式开启，实体、正向边、反向边按 ID 范围分页，每页最多 1024 条、编码目标 8 MiB，单条超大记录允许独立成页 |
| `GRAPHDB_INDEX_ADJACENCY_PAGES` | v2.4.0 新增，默认 `false`；依赖范围页，升级全部相关节点后显式重建；业务写入不自动转换无根桶。详见[邻接与合并契约](entity-range-paging-implementation.zh-CN.md#邻接-id-树与局部合并) |
| `GRAPHDB_ENTITY_PAGE_PACK_MAX_BYTES` | 仅旧写布局生效；默认 32 MiB，限制合并实体页的估算内存；旧单个逻辑分片可以超过此值 |
| `GRAPHDB_READER_INDEX_CACHE_MAX_BYTES` | 默认 256 MiB；解码实体页缓存另受该值一半的上限约束 |

文件系统必须支持文件锁、原子重命名及文件/目录同步。不支持网络共享目录、多进程共享目录，
也不能在运行中从外部修改数据文件。目录锁覆盖服务和离线 CLI；在线管理使用 HTTP API。
第二个进程立即失败，进程异常退出后操作系统自动释放锁。

[2.3.0 已包含的完整恢复保护](product-p0-p1-review5-2026-10-03.zh-CN.md)还锁定独立 WAL/Raft 目录，避免在 data 目录空闲时备份活动日志或在恢复续跑时替换它。完整运行状态命令及嵌套目录限制见[产品运维](product-operations.zh-CN.md#完整运行状态灾备)。锁文件保留原 inode，不能手工删除来解除占用。

## 持久化和读取

数据文件先分别同步并重命名，每组最多 64 个写任务、4 个工作线程，再对受影响的目录
合并同步，最后发布引用这些文件的 manifest/catalog。创建目录时同步其父目录。
manifest/catalog 仍以单文件原子替换发布；失败可能留下无引用文件，不承诺多文件原子事务。

实体页、边分片、二级索引、快照直接使用文件随机读取，保留列/行组筛选、内容及 schema 校验。
操作完成或取消后释放文件句柄和解码并发名额。图缓存根据本地发布事件失效，包括恢复旧版本。
解码后的 manifest 缓存限制为 8 MiB、4096 项，并通过文件写入代次失效，避免恢复后复用同版本旧 head。
缓存未命中时直接读取当前磁盘 manifest，跳过可能仍持有发布前读取结果的字节缓存和共享在途读取。
旧式单文件快照及备份/任务结果也从文件句柄解码，避免在内存中再保留一份完整压缩文件。

HTTP 读视图保护尚未打开的引用文件。GC 按进入代次延迟回收旧视图需要的文件，新查询仍可进入；
显式清理提交、清空租户和恢复等待当前读视图结束，普通提交继续发布新的不可变文件。
任务引用继续持久化，执行存活状态由进程内注册表维护。freshness 接口只反映本进程，
旧磁盘 heartbeat 不作为远端 reader 集群状态。
共享缓存加载会持有读视图直到加载结束，即使发起加载的 HTTP 请求已经取消。

分页游标绑定持久化租户代次，覆盖索引页和图回退路径。恢复或清空租户后，旧游标明确报错，
即使新数据的版本号相同也不会混读。初始代次仍接受旧格式游标；正常提交及同代次索引更新不改变代次。
固定游标引用的目录或数据文件不可用时，不回退到另一份图继续分页。
运行查询列表和取消接口只操作本进程注册表，保留租户校验，不等待读视图或维护完成。

本地 GC 的候选页最多包含 512 个文件；在文件之间检查工作预算，达到 50 ms 或
16 MiB 候选文件字节数时让行。每批至少处理一个文件，保证游标前进；这是协作式预算，
不是严格延迟上限。显式删除总预算和 dry-run 保留。续跑游标是不透明值，可包含清理阶段标记；
孤儿快照扫描在暂停和恢复后仍保护保留版本、当前版本和未完成的未来版本，不会转入整版本删除。
调用方应原样传回返回的游标。扫描开始后修改的文件留给
后续 GC，不再保留整个前缀的候选列表。单个目录的文件名仍需排序，单个大文件也可能
超过时间预算。GC 先排除仍被旧读视图占用的孤儿索引，避免在租户锁内重复解码本轮无法
回收的文件；可回收时再从文件句柄校验内容和租户，删除前重新检查引用保护。

批次之间释放租户锁、读视图和任务执行名额，再重新检查 manifest/catalog；批内共享
目录同步屏障，取消或失败时也会完成屏障。索引重建的 backfill 阶段仍保留写入背压，
cleanup 使用同一批次机制。进程内活跃 GC 任务不因心跳延迟而被重复启动。

## 就绪与内存预算

`/v1/readiness` 会验证目录存在，并创建、写入、同步、删除一个很小的临时文件；
并发探测复用同一次检查。目录可读但不可写时返回未就绪，`/v1/health` 仍是存活检查。

Compose 支持同时设置 `GRAPHDB_MEMORY_LIMIT`、`GOMEMLIMIT` 和读写缓存字节上限。
默认不限制容器或 Go 运行时内存，两个图缓存默认各 512 MiB。有限内存部署可从以下配置开始：

```sh
GRAPHDB_MEMORY_LIMIT=7g GOMEMLIMIT=5GiB docker compose up -d
```

这不是容量保证。`GOMEMLIMIT` 是 Go 软内存预算，不是 RSS 硬上限；需为解码、快照、
栈、文件访问和其他缓存留出余量，并用实际数据验证包含后台维护的负载。

## WAL 与状态查询

Direct 写入返回已发布结果。WAL 模式下 202 表示持久化接管，尚不等于图版本已提交。
可轮询响应中的 `status_url`，或使用 `Prefer: wait=committed` 等待终态。
状态地址为 `/v1/ingest/batches/{source}/{collector_id}/{batch_id}`；旧 writer 路由返回 501。
重启通过原有 WAL 格式恢复已接受请求。
等待期间若 WAL 服务故障或被强制关闭，等待立即结束并返回服务错误；请求自身取消或超时也会结束等待。
这些错误不撤销已持久化接管的批次。保留响应的 `Location`，恢复后查询状态，或使用相同批次身份重试；
正常关闭前已完成的批次仍可取得最终结果。
2.3.10 起，sync 模式在帧 fsync 后原子发布带校验和的 `.durable` 边界，再返回确认。
恢复只自动截断已验证边界之后的末段坏头、坏 CRC 或全零后缀。持久化前缀内的损坏、
边界文件损坏、无边界旧 WAL 中无法判断是否确认的完整坏帧，仍保留原字节并拒绝启动。
旧 WAL 验证成功后补建边界；旧版半帧尾恢复语义保留。备份须保留整个 WAL 目录和 `.durable`、`.checkpoint`，
不能手改边界绕过损坏。OS durability 仍允许丢失未刷盘后缀；正常关闭／轮转会先同步数据再推进边界。
每个 sync 组增加一次边界元数据同步，本补丁不宣称吞吐提升。

Direct/WAL ingest 的 manifest 发布后，索引在进程内按版本顺序追赶；相邻的待执行批次合并为有界增量，
超过 8192 个变更引用时分批追赶。全进程最多保留 8 项后台索引工作；达到上限后，当前 ingest 在释放租户锁后同步完成索引。
`committed` 仍表示图数据已经持久化并可读，索引滞后时查询
使用符合 `min_version` 的图视图。`/v1/commits` 仍等待自身的索引更新，并与 ingest 共用排序链。GC、恢复及目录关闭
等待相关文件引用释放。进程中断可能留下滞后的索引，但不会丢失已发布的图提交。

本地索引重建进入同一条有序索引发布队列；ingest 可继续发布，后续索引在重建之后追赶。
任务完成表示已处理其捕获的版本；持续写入时，更新的图头仍可能等待后续索引工作。
本地 compact 或重建期间，追平工作有界合并需求，不保留中间图，也不预留维护仍需使用的内存；
队列只保留旧标量值和旧边端点，最多 8192 个变更引用，字节估计上限为 `min(维护预算 / 64, 8MiB)`。
等待前序工作和图构建预算后才加载最新图；若等待期间新写入增大了图，先释放不足的预算，再按最新估算申请。
预算等待不持有租户锁或保留中间图，期间继续合并追平需求；超预算的构建独占维护预算。
取得足够预算后固定输入，对匹配的基准 catalog 增量追平；
超过上限、schema 变化或基准不匹配时回退全量重建。显式 `/v1/commits` 仍等待自身索引更新。
进程中断后，已配置的自动维护可修复 stale catalog；关闭自动修复时可显式重建。
副本和远程回填仍保留写入准入屏障。

## 升级、备份与恢复

先停止旧服务并备份数据目录，再用本版打开。沿用本地 Parquet/WAL 格式。
检测到 PostgreSQL 协调标记时拒绝接管；本轮不提供远端搬迁或协调 head 转换，不能删除标记强行启动。

使用备份恢复及完整性审计 API。需要抵御整盘丢失时，配置
[对象存储快照备份](object-backup.zh-CN.md)，通过 `destination: object` 创建远端恢复点。
原有同盘备份继续可用。回退程序版本必须停服，并使用保留的目录备份。

本地备份清单只校验其不可变备份记录；旧清单中附带的在线 head、索引引用不再作为恢复依赖。
后续提交或索引 GC 不会使这份恢复记录失效。

恢复先在同一文件系统的暂存目录构建并校验完整租户。保留任务和本地备份时只暂停目标
租户目录的文件访问，每个保留目录仅同步一次；其他租户可继续读写。全局文件访问锁仅用于
目录切换和代次更新，旧目录递归清理在释放全局锁后进行。
持久化切换日志在新目录提交前保留旧目录；启动时先回退未完成的切换，再接受请求。
多个目录重命名不是原子多文件事务。需要为新旧两份数据预留空间。
若磁盘错误导致回退无法完成，服务拒绝后续操作，直到重新打开目录并成功恢复。

恢复结果及代次随新目录一起发布。若仅任务终态写入失败，重试只补做收尾，保留恢复后已经确认的新写入，
也不再依赖源备份可用。租户已被再次恢复，或旧任务缺少可验证的发布断点时，重试明确失败，不再次覆盖。
远端快照下载和解码不持有目录切换锁；排队的文件访问和恢复发布会响应请求取消。

清空和恢复会暂停 WAL 新受理、排空已受理请求，再取得租户排他读视图。
WAL 绑定的租户代次保存在租户目录之外，并在清空或恢复时推进，避免离线重建后重放旧租户请求。
不带代次的旧 WAL 仅允许在初始代次恢复。并发任务只有参数相同时才复用；不同参数返回冲突，
不会静默使用另一份恢复源、备份目标或 dry-run 任务。

## 验证与性能

当前发行范围见 [2.3.0 验证记录](validation-v2.3.0.md)，具体二进制资格以完整发行流程与包内证据为准。[2.1.2 验证记录](validation-v2.1.2.md) 和[写入长尾报告](performance-write-tail.md) 属于旧版；该历史版本的 30 分钟负载提前停止，不计为通过，也不豁免当前发行门禁。
[2.0 验证报告](performance-v2.0.md)及以下旧版报告仅作历史参考。

日常优化先运行代表性单轮对比，出现明确退化后才定向复测。已有工具
`scripts/local_disk_optimization.py` 比较优化前后的本地二进制，复用相同停服数据副本，
覆盖 direct/WAL、混合读写、导出、压缩、备份恢复和进程冷读。
方法、结果及局限见[本地性能优化记录](performance-local-disk-optimization.md)。
[第二轮优化记录](performance-local-disk-optimization-2.md)覆盖目录哈希、实体分页、HTTP 编码、
Parquet 行组布局和增量索引。

`scripts/release_gate.sh` 包含单元、vet、race、2.x 契约、SDK、direct/WAL HTTP、负载及重启一致性验证。
`GRAPHDB_GATE_SOAK=1` 增加含压实、GC、索引重建的 30 分钟混合负载。
HTTP 功能验证默认缩小图缓存以实际执行持久化索引读取，不作为性能容量测试。

完整发布验收可选三组比较：`ffa85414` 对象存储、该版本已有本地模式、本地磁盘新版。使用相同 Linux 卷和资源限制，
约 1 万/10 万实体、direct/WAL、4 写客户端和 16 读客户端，预热 60 秒、测量 5 分钟，轮换顺序重复 3 次。
记录已发布吞吐、p50/p95/p99、接管到可读延迟、CPU/RSS、磁盘 I/O、fsync 和文件句柄。
进程冷缓存与操作系统页缓存状态分别报告。

相对原本地模式，目标为混合吞吐和冷读 p95 各改善至少 10%，其他尾延迟/导出耗时回退不超过 5%，
峰值 RSS 增长不超过 10%。测量噪声、正确性失败与缺失场景必须明确记录；历史版本报告不能证明本版收益。

### 可选的完整对照测试

```sh
scripts/local_disk_compare.sh
```

从包含完整 Git 历史的仓库运行，使用 Docker/OrbStack。脚本构建指定基线，给基线
加入相同的 fsync 观测计数器，然后构建当前 worktree；使用隔离容器和 Linux 卷。
默认覆盖两种图规模、两种接入模式，混合负载与维护序列均预热 60 秒、测量 300 秒，
另做 30 次进程冷读，轮换顺序重复 3 次，完整运行需要数小时。
短流程检查可以传入 `--entities 10002 --warmup 2 --measure 10 --maintenance-seconds 0
--cold-samples 2 --repeats 1`，不能用该短测判断性能达标。证据及源码校验值保存在
`capacity-runs/`，Linux 命名卷保留供复查。GraphDB 的 fsync 计数不包含 MinIO 内部调用。
所有对照组统一使用 60 秒写入排队超时；默认 2 秒会在 10 万实体 direct 负载中拒绝排队请求。
排队时间仍计入写延迟，此设置只用于对照测试，不改变服务默认值。
对照组统一设置 120 秒 reader catch-up 上限，使 10 万实体冷快照导出记录完整加载耗时，
而非触发默认 2 秒 freshness 截止时间。正确性持续负载的 HTTP 客户端也等待至多 120 秒，
覆盖维护期间的 WAL 等待；实际延迟仍保留在报告中。
定时负载客户端保留同一幂等键，按 `Retry-After` 重试可重试的 429；重试等待计入端到端接入延迟。
背压响应单独记录，不能计入已发布吞吐。
固定 host 数据集含未建索引的 `loadtest_revision` 字段，每批按确定序列更新，预热与测量间也会改变。
版本增量与成功批次数不一致时测试失败，防止把无变更响应计入已发布吞吐。
WAL 可读延迟包含终态确认、10 ms 轮询及一次成功的 `min_version` 实体读取，属于首次可读延迟的上界。

索引发布后的清理阶段释放原任务执行名额，本地 GC 每批重新申请全局执行名额，让 compact 在批次之间继续推进，同时保留并发上限。每次 GC 固定目录候选集，避免持续写入让最后一页不断延长；本地任务存活由进程内执行者判定，不依赖持久化心跳。


## 写入、维护和内存

`main` 发布 2.x 本地版。2.1 沿用 2.0 数据目录，复用前须停止旧进程；替换 1.x 时使用新目录。
不提供 1.x 迁移、旧 MD5 接口或跨主版本回滚；旧版 Parquet manifest 会明确报错。
S3 只承担可选快照备份和按需恢复。

实体、边和顶层邻接目录使用 256 个写时复制分片，旧读视图复用未变化分片。
`data_hash` 使用带算法标识的分片 SHA-256，只更新受影响分片，根摘要固定处理 32 KiB；
不再为每次提交扫描整图编码。冷加载仍需构建完整图和初始摘要。

增量实体、正向边和反向边索引按受影响分片访问。超过 8192 条变化引用后分批追赶，
不再仅因积压阈值触发全量重建。
索引正在排队或增量更新时，健康接口返回 `updating: true`，自动维护等待本次更新完成，
避免重复全量重建争用维护资源；更新失败后下一轮仍可修复。手动重建请求继续执行。

文件发布每批最多 64 个任务，四个共享编码名额，
在文件之间检查 16 MiB / 50 ms 预算。单个大文件及最多四个在途文件可能超出合作式预算，
引用它们的 catalog 必须等待所有数据和目录同步完成。

全量实体页、增量实体页／正向边和反向边共用上述文件写入队列。独立文件包可以并行完成，
实体记录和 catalog 仍等待其引用的文件包与目录同步；Raft 应用使用同一队列，
回滚日志和提交持久化屏障保持不变。

主索引仍优先准备和发布，再准备反向索引，避免两者争用编码名额推迟主 catalog。
compact 的分片快照与兼容全量记录共用原有文件写入限额并行准备，包括可恢复任务路径；
两者完成后才发布 manifest。

流式 Raft 快照仅为实际保留的文件重建父目录；GC 留下的空版本目录不进入只保存文件的归档。
维护发布仅在同一次应用屏障内复用目录祖先校验。独立目录同步有界并行，全部完成后才写入持久化提交标记；
回滚前镜像与恢复要求保持不变。

实体／边页、二级索引数据、commit／ingest 行和全量快照记录使用 Parquet delta byte-array
字符串编码、数值字典及 Snappy 压缩。字符串前缀编码减少宽行 schema 的逐行字典分配，
同时保留重复元数据的紧凑存储。实体页每个行组最多 4096 行；每个逻辑分片至少有
512 个物理行时按分片对齐，包含更小分片的文件包保留 512 行布局，避免每个小分片
都生成宽表页脚。两种布局均保留分片统计裁剪；列 schema 和逻辑哈希不变，
仍可由既有读者解码，编码后的文件大小可能不同。装载快照在实体规范化后构建一次实体索引，
随后只追加边索引，避免再次构建实体索引。

`GRAPHDB_MAINTENANCE_MAX_BYTES` 默认为 512 MiB；排队索引图和正在执行的索引/快照共用
同一预算，队列预留额度直接转入执行。最多两个构建并行；超过预算的单个构建独占执行，
避免无法处理大租户。缓存使用已有字节上限；结合 `GOMEMLIMIT` 和容器内存上限统一评估，
预算是估算准入，不是硬 RSS 上限。旧版本共享分片和紧凑摘要减少了保留读视图的额外开销。

本地同步索引更新的等待队列也按上述有界规则合并，适用于超过预算的大图。
版本必须连续且 writer fence 相同；合并后的调用方等待同一次 catalog 发布并取得其索引错误。
Raft 应用仍保留每条日志的事务边界。合并减少等待队列中的过期编码，不会提高内存预算。

本地实体页、二级索引和边分片读取先取得 Parquet 解码准入，再打开文件。等待解码的查询
不会占满对象读取名额，候选扫描和后续解码共用此次准入。当解码上限至少为 2 时，大数据
解码最多占用总名额减 1，给控制元数据和写入发布所需的基础图装载保留容量；两类工作共用
原来的总上限。上限为 1 时仍串行执行，未限制的配置仍保持未限制。

写缓存为空时，首次写入可以复用已驻留的读图，但须先读取权威 manifest，并核对其 ETag、
完整读取集合和图版本。写入使用写时复制，旧读视图保持不变；manifest 不同仍须装载当前图。
显式指定 expected version 的写入同样遵循此校验。

压缩直接编码已经规范化的图快照，避免通过 JSON 再解码并保留第二张完整图。
存储内容哈希仍使用原有 JSON 载荷，外部提供的快照记录继续规范化；
完整快照记录、分片快照及其发布持久化屏障均保留。

GC 每批至多访问 512 个候选，在对象之间检查 50 ms / 16 MiB 预算。旧读视图仍需使用的文件
延迟到后续批次回收，期间新查询继续进入。大对象可能超时，持续长读可能推迟旧文件回收。指标
`graphdb_maintenance_phase_seconds` 区分等待、构建、持锁和同步；
`graphdb_maintenance_estimated_bytes` 显示执行和排队预留，不表示实测 RSS。

详见[版本边界](naming-and-compatibility.zh-CN.md)、[摘要规范](content-hash-v2.md)和[当前发行验证](validation-v2.3.0.md)。

## 索引失败与 WAL 准入

WAL HTTP 请求在解码 JSON 前获取有界写入槽，但受理时不执行图发布背压检查。
commit tail、对象存储与 CAS 压力由 flush worker 检查；已受理批次重发仍能取得原确认。
WAL 磁盘／队列上限及租户生命周期检查保持生效。直接 ingest 仍在解码前检查发布背压。
未准备分组会拆分以利用剩余 commit-tail 容量，即使组大小未超过总上限；tail 满时仍等待
compact。已持久化 PREPARED 的组保留原子发布，不能拆开。

后台索引发布最多尝试三次，包含首次更新；只重试明确的对象存储不可用、CAS 冲突和
操作超时。每次重试前释放旧读视图、构建／内存预留及队列位置，然后重新捕获当前图，
在原 writer fence 下排队重建。八个后台 worker 的总限额包含正在退避的任务，避免重试
扩张为无界队列。永久错误或重试耗尽后，索引健康仍显示 stale，由自动维护或显式 rebuild
修复；已经发布的图提交仍然持久化。合并等待及前驱等待均响应取消，取消的队列项仍保留
前驱顺序屏障，后继不能提前发布。图已发布后的取消不会回滚已提交数据。

## 2.3.10 候选追加审查

已有目录的安全检查可并发进行；目录创建和失败的父目录 fsync 重试仍排他执行，避免在目录尚未持久化时确认其下对象。

图缓存除本地发布通知失效外，再按 TTL 重验 manifest。`GRAPHDB_POLL_INTERVAL` 默认 2 秒；这不增加共享目录或多进程 reader 部署支持。解码后的边和字段 postings 缓存分别使用 `GRAPHDB_READER_INDEX_CACHE_MAX_BYTES` 的四分之一，均有 LRU 容量上限；实体页仍为二分之一。

单机 WAL 把已完成历史折叠为带校验和的 `.checkpoint`，保留所有未完成请求及 PREPARED 计划，先同步检查点，再删除旧段。一个故障租户保留自己的输入，不再钉住其他租户的全部历史；修复底层故障前它仍保持 pending。`.durable` 标记是否必须存在检查点，必需检查点丢失或损坏时拒绝启动。备份、恢复必须包含整个 WAL 目录。存在 checkpointed pending WAL 时不要直接降级；先排空，或保留当前程序和完整目录。

全量索引重建逐字段写入并释放 postings，复用 kind 的 ID 顺序，schema 与显式重复定义只扫描一次。输出所有索引字段仍须处理相应字段值，不承诺重建耗时与字段数无关或整个过程恒定内存。

固定 64 桶导致的实体页／边分片写放大仍在处理；缓存、WAL 和重建修复并未解决它。其有界写入回归通过前，发行资格保持未完成。

范围页必须分两阶段启用：先升级所有读取节点和 Raft 副本，再配置 `GRAPHDB_INDEX_RANGE_PAGES=true` 并重建索引。旧二进制不能安全分页新范围目录。降级前用新二进制关闭该开关，逐租户重建索引并验证，再切换旧程序。详见[实现与启用说明](entity-range-paging-implementation.zh-CN.md)。

### 未发布的审查修正

sync WAL 每组确认前同步段文件，再原地同步预分配的双槽校验 `.durable` 文件。启动可读取并迁移旧36字节边界。单槽损坏时不会用较旧边界截断不明尾部；已确认帧损坏或两槽均损坏仍拒绝恢复。旧程序不能读取新边界格式，降级前先排空 WAL；备份保留完整目录。只有持有 WAL 目录锁的进程才能清理遗留 marker/checkpoint 临时文件。

checkpoint 按完成字节摊销触发，门槛为待处理字节与一段大小的较大者，不再每128次完成重写整个积压。并发满盘触发按代次合并；逐请求流式写入原 v1 CRC+JSON 格式。恢复仍扫描 WAL，构造 checkpoint 仍占用 WAL 写协程。队列容量必须小于 WAL 总容量减去控制预留。驻留的持久化 PREPARED 计划计入队列压力；已准入的在途 flush 可能超过准入预算，该配置不是进程 RSS 硬上限。关停重试保留退避，延迟背压的样本会按观测窗口过期。

大小写目录检查缓存最多256目录、8MiB，并核验父目录身份、修改时间和大小；逐层 symlink 检查保留。GC 只在一次运行内复用邻接保留集合，根发布时失效；坏 catalog 的索引清理仍报错，但继续独立的快照、任务和死信保留清理。本地手动备份引用的任务元数据与结果不因任务 TTL 删除；HA 排队任务不按任务年龄删除。死信重放的提交前错误保持 pending，租约过期后继续使用同一持久化尝试身份。manifest 修复遇到同版本不同提交 ID 会拒绝猜测；当前提交没有 parent-ID 链，这也不构成孤儿提交已发布的证明。

被裁剪的远程边页只把有上限的 footer统计（每页最多256KiB）放入现有有界对象缓存，复用重复扫描，不驻留或落盘被丢弃的载荷。
