# 大图分片第一轮读路径优化

2026-11-09，分支 `codex/large-graph-sharding`。本轮基于未提交的大图分片核心实现，只优化分区批量读取与双向邻接预取，不扩展功能范围。总体能力和未实现部分见[实施说明](large-graph-sharding-implementation.zh-CN.md)。

## 改动与保护边界

`Store.Read` 的多 key 请求现在复用本次请求已经校验、解码的不可变树页。相邻 key 不再重复读取相同的根与叶；缓存以完整根元数据为键，错误 count/边界不能绕过校验。缓存只在单次 RPC 内存在，计账包含编码长度与解码元数据估算，上限 4 MiB、128 页；满后继续正常读取，不再缓存。单 key 和扫描路径不启用此缓存。

双向邻接无类型过滤时，底层读取批次由 64 对齐为迭代器实际消费的 16 条，减少反复预取尚未消费的记录。有关系类型过滤时继续按 64 条扫描，保护稀疏过滤的 RPC 数量。单向遍历批次保持 64。

响应仍最多返回 4 MiB，未返回 key 的续读位置、结果顺序、统一图版本和根校验保持原契约。下一次请求重新读取并验证物理页，GC、分区退役和磁盘损坏不会被长期页缓存遮蔽。没有新增依赖、配置项、持久化字段或协议版本。

## 对照方法

OrbStack Linux arm64，`golang:1.27.3-bookworm`，默认 `GOMAXPROCS=18`；源码固定归档后解压到容器本地目录，文件存储测试也使用 Linux 本地临时目录。Go 模块离线复用现有缓存。基准命令：

```sh
go test ./internal/partition -run '^$' \
  -bench 'Benchmark(PartitionReadBatch|DistributedBothEdges)$' \
  -benchmem -benchtime=500ms -count=5
```

批量点查：4096 条记录，单批 128 个 key，分别测相邻和分散位置。邻接：合成单分区数据，用于隔离 Lookup 的批量读取开销，测试首项、512 次双向访问及每 64 条仅一条匹配的稀疏类型过滤。该基准不经过 HTTP、Raft 多数派或完整图约束构建；`rpc/op` 计数的是本地 Remote.Read 接口调用，`row_bytes/op` 是返回行 key/value 字节之和，不是线上总网络流量。

基线和候选均重复测量，以下使用同一组最终场景各 5 次的中位数。两次基线复测中，共有场景中位数漂移为 -3.4% 至 +4.5%；宿主仍与其他项目共享资源，计时可能波动。文件读取为热操作系统页缓存，本表不是冷盘或整库吞吐测试。

| 场景 | 时间 ms/op，前 → 后 | 分配 MiB/op，前 → 后 | 耗时下降 |
| --- | --- | --- | --- |
| 内存存储，128 个相邻 key | 12.864 → 0.281 | 10.609 → 0.179 | 97.8% |
| 内存存储，128 个分散 key | 12.604 → 4.923 | 10.642 → 2.881 | 60.9% |
| 文件存储，128 个相邻 key | 17.688 → 0.401 | 11.918 → 0.198 | 97.7% |
| 文件存储，128 个分散 key | 17.617 → 6.965 | 11.958 → 3.217 | 60.5% |
| 双向邻接，首项，无类型过滤 | 22.572 → 0.845 | 22.716 → 0.546 | 96.3% |
| 双向邻接，全部，无类型过滤 | 342.870 → 12.398 | 328.941 → 8.271 | 96.4% |
| 双向邻接，首项，稀疏类型过滤 | 91.686 → 4.758 | 90.701 → 3.119 | 94.8% |
| 双向邻接，全部，稀疏类型过滤 | 91.698 → 4.841 | 90.704 → 3.119 | 94.7% |

资源计数与时延结果一致：

- 相邻 128-key 批量点查：树页读取 256 → 3，页数据读取 3,861,504 → 48,930 字节。
- 分散批量点查：树页读取 256 → 65，页数据读取 3,861,504 → 1,212,174 字节。
- 无过滤双向首项：行数据 161,856 → 40,464 字节（-75%），分区读取调用仍为 4。
- 无过滤双向全量：行数据 2,346,912 → 647,424 字节，调用仍为 66。
- 稀疏类型过滤：行数据仍为 647,424 字节，调用仍为 16；收益来自页读取与解码复用，没有通过增加调用次数换取较小批次。
