# 本地磁盘版：第五轮 P1 修复

日期：2026-09-17。工作区 `/Users/livesite/Documents/GraphDB-local-disk-v2`，分支 `codex/local-disk-v2`。

修复第五轮审查确认的三项 P1。保留此前的本地磁盘、对象备份、性能优化及四轮修复；没有提交、推送或合并。

## 1. 导入与 WAL 共用写入顺序

独占本地目录中的 `Ingest`、`IngestDurable` 和直接提交，在取得租户写锁前暂停该租户的新 WAL 受理，并等待已受理请求完成。导入和死信重放复用这一入口，不能再占用尚未发布的 WAL 准备版本。

取得租户写锁后即可恢复 WAL 受理；新请求的准备和发布仍需同一把写锁，因此不会越过正在执行的直接写入。等待不占用全局 WAL 写入能力，其他租户可以继续工作。

任务等待 WAL 时释放租户任务名额和全局执行名额，等待完成后重新取得。这样，即使只有一个任务执行名额，compact 也能运行并解除 WAL 背压。恢复等使用同一等待入口的任务采用相同规则，避免它们与导入互相占用名额。取消和退出继续受原任务上下文控制。

## 2. WAL 重试复用持久化准备计划

请求已有持久化 PREPARED 时，重试检查计划一致性并复用原记录。manifest 或批次结果暂时保存失败，都不会为相同计划不断追加完整 PREPARED。重启恢复后的请求也采用此规则。

批次中已准备为身份冲突失败的请求，在补写失败记录或终态重试时保留原结果和准备计划，避免生成新的 flush ID。发现准备计划实际变化时仍明确报错，不能覆盖持久化证据。

没有改变 ACCEPTED、PREPARED、图发布、结果保存及终态的持久化顺序，也没有降低同步落盘默认值。

## 3. 失败状态缓存释放大对象并限制容量

终态完成时释放请求 items、前置条件及 Prepared 等大对象，保留 `Wait` 所需结果和状态查询标识。调度器使用的 FullSync 标志保持不变；完成日志和 trace 单独保留 flush ID。

失败状态缓存同时限制为最多 1024 条，以及不超过 `min(QueueMemoryBytes, 4 MiB)` 的估算字节预算。估算采用序列化状态、缓存键及每项固定开销，不是精确的 Go heap 上限。超大条目直接跳过缓存；淘汰时清除旧引用，并校验条目身份，避免删掉同键的新请求。缓存未命中继续读取持久化失败结果。

## 实际验证

环境：OrbStack / Docker Engine 29.4.0，Go 1.25.14 Linux arm64。源码、数据和 WAL 位于独立 Linux 验证卷；unit/race 容器限制 4 CPU / 6 GiB，HTTP 和内存探针限制 2 CPU / 4 GiB。

| 验证 | 结果 |
| --- | --- |
| `go test -mod=readonly ./...` | 通过，包含 Go SDK |
| `go vet -mod=readonly ./...` | 通过 |
| storage/httpapi 定向 race | 84 个顶层测试通过，无数据竞争报告 |
| direct/WAL 真实 HTTP 门禁 | 通过：图查询、来源治理、幂等写入、索引、任务、本地备份恢复、导出、compact/GC、重启后快照一致 |
| HTTP 混合请求 | 两种模式均使用 4 写入与 16 查询客户端，10 批、每批 20 条；报告全部请求无错误 |
| Python SDK 真实 HTTP | 12 项通过 |
| 源码一致性 | 验证完成后，产品源码与运行快照一致 |

聚焦回归覆盖：

- 32 KiB WAL、16 KiB segment、约 4 KiB 请求，在 manifest 和批次元数据两个故障阶段分别重试至少 8 次，均只留下 1 条 PREPARED；模拟服务中断并重新打开后完成至版本 1，幂等重放不增加版本。
- WAL 已准备而 manifest 发布失败时，真实导入任务等待；另一租户正常写入。故障解除后，WAL 发布版本 1，导入发布版本 2，两个实体均存在且服务就绪。
- 单任务名额下，导入等待被背压阻塞的 WAL，同时 compact 成功解除背压；最终 WAL 和导入均完成。
- 12 条包含大失败结果的请求触发缓存淘汰，缓存无请求 items 引用、队列计数归零；被淘汰结果的 Status 和原 Wait 仍返回失败详情。

复用审查时的同一内存探针：64 条请求各带 1 MiB 字段，队列预算 4 MiB，逐条因 expected_version 不匹配完成失败。缓存直接引用的请求字段由修复前的 **67,108,864 字节降为 0**。本次强制 Go GC 后净 heap 增长为 **342,800 字节**；修复前为 70,836,552 字节。heap 数字是单次故障回归观察，受分配器和缓存状态影响，不据此推算容量或吞吐。

首次全量/race 检查曾捕获请求释放引起的 flush ID 日志缺失及 FullSync 并发读写；已修正并重新运行上述最终检查，初次失败日志单独保存。
