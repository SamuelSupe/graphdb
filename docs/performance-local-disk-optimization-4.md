2026-09-17。工作区 `/Users/livesite/Documents/GraphDB-local-disk-v2`，分支 `codex/local-disk-v2`。保留原工作区及所有既有改动，未提交、推送或合并。

## 改动与依据

### 1. 恢复时继承索引布局配置

真实 HTTP 恢复中发现：`restoreLocalTenantBackupTask` 新建临时 TenantStore 后，只继承实例 ID，遗漏了实体索引配置。构造函数默认启用逐实体索引文件，而服务默认关闭。恢复因此重新生成了 10002 个逐实体文件，同时放弃实体页打包，增加大量文件写入和同步。

临时存储现在继承 `WriteEntityRecords`、`UseEntityRecordsForRead` 和 `EntityPagePackMaxBytes`。用户明确启用逐实体文件时仍然保留该布局；关闭时采用现有打包路径，打包大小也遵循服务配置。恢复目录切换、代次保护、读视图锁及 WAL 排空顺序保持原逻辑。

新增行为回归覆盖启用实体文件、关闭并打包、关闭且限制打包大小三个场景；重新打开数据目录后核对目录布局，并通过持久化索引读取全部测试实体。该测试在优化前稳定失败，在修复后通过。

### 2. 整图快照分批编码

当前代码的 compact 分配诊断显示：整图快照编码累计分配约 923 MiB，其中全部中间行切片的直接分配约 278 MiB。这里是累计分配量，不是同时存活的内存。诊断窗口还有后台索引写入，不能把窗口的全部分配都归给 compact。

现在逐实体/边生成中间行，每 16384 行写入一个 Parquet 行组并释放 Arrow 批次，避免积累整图中间行和整图 Arrow 列。JSON 规范化、输入快照和压缩结果仍会完整保留，因此没有宣称整个操作使用常量内存。

列定义、全局 ordinal、codec、逻辑内容哈希和发布顺序保持兼容，物理行组数量改变。失败或取消时不发布部分编码结果。新增回归覆盖空图、跨行组的宽实体与宽边、嵌套字段和完整规范化内容一致性。

### 3. 索引任务进度与替换任务的竞争

最终全量单元检查实际触发 `TestCreateIndexBackfillsSchemalessFieldAndDropRemovesIt`：删除索引时报 `object write conflict`。

索引定义变更可启动新重建任务，此时旧任务可能仍在写入 cleanup 进度。旧进度写入未与新任务发布共用启动锁，还可能覆盖新任务的共享运行标记。修复后，进度保存复用已有任务启动锁；旧任务继续保存自身进度，但不能修改新任务的运行标记。

新增确定性回归在旧实现中复现标记覆盖，修复后通过。另将原失败用例与新增回归连续运行 30 次，全部通过。没有通过放宽断言或忽略写冲突绕过失败。
