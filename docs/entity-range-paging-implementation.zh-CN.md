# 实体与边范围分页：实现与启用

范围页用于消除实体、正向边、反向边的整桶增量重写。外层保留 64 个逻辑桶；桶内按原始 ID 字节顺序排列不可变物理页。每页最多 1024 条逻辑记录，Parquet 文件以 8 MiB 为目标上限；超限继续拆分，单条超大记录独立成页。

## 启用与兼容边界

`GRAPHDB_INDEX_RANGE_PAGES` 默认 `false`。新程序始终能读取两种目录，只有显式配置 `true` 才写范围页。三个 Compose 示例也接受该变量。

1. 保持开关关闭，升级所有读节点、写节点和 Raft 副本。
2. 确认相关节点均支持范围页后，统一开启该变量。
3. 对已有大租户重建索引。已明确标记为当前 64 桶的旧单页可按触及桶迁移；legacy 256 桶或归属不明确的目录通过完整重建迁移，避免向两个候选桶重复写入。

旧二进制不能安全分页范围目录。互操作实测曾让旧程序仅枚举出 2050 条中的 762 条，因此不能依赖旧程序自动回退，也不能把 `LayoutVersion` 当成能力协商。

需要恢复旧索引布局时，先停止新格式写入，用新程序关闭该变量并逐租户重建，再校验实体、边、反向邻接和索引健康。新程序、v2.3.8 源码编译的存储探针、再次启动的新程序已验证这一索引转换流程，包括旧程序的 GC 和读写。本验证只覆盖索引与图对象；WAL、Raft 数据目录及运行态快照仍须满足其各自的版本兼容要求，不能据此直接降级整个数据目录。

## 存储与读取契约

`EntityPageSpec` 和 `EdgeShard` 仍代表逻辑桶。父级 codec 标识范围布局；已有对象引用的版本化 `Role` 保存下界、排他上界和文件字节数，引用中同时保存 key、条数、内容 hash、schema hash 和物理 codec。这些字段进入已有目录序列化与目录 hash，不增加 Parquet 目录列。

路由目录 hash 覆盖有序范围、对象引用和校验信息；数据 hash 独立于路由边界。删除空页时扩大相邻范围可以只更新目录，继续引用原对象。范围页一页一个文件，不与其他页重新打包。旧 pack 保留读取支持，关闭开关时仍使用旧写布局及其原有 pack 限制。

增量更新按触及物理页归组，每页读取一次。只有发生变化的页重新编码；溢出页均衡拆分。`EntityRecord` 保持可选，分裂不更新未变化实体的定位提示。发布前沿用已有图版本、租户 generation、writer fence 和目录 CAS 检查；新页先持久化，目录整体发布。失败或取消保留原目录，发布结果不确定时保留可能已被引用的对象。

点读二分定位物理页，批量点读按物理页分组。实体和边扫描、正反向邻边分页从游标对应页开始，收集够结果即停止。邻边在关系类型之间惰性归并，每个迭代器只保留当前页；同桶稀疏候选仍可能访问多个页，其过滤工作计入查询成本并响应取消。查询路径不会先拼接整个桶。

目录编译缓存按租户、版本和目录 hash 隔离，限制为 512 项及估算 64 MiB；物理页复用现有按字节限制的缓存。缺页、内容不符或无效范围返回不可用或错误，不视为空结果。旧读视图与 GC 的并行保护沿用本地文件 epoch。删除历史索引／分片快照目录不再误报为根发布，使释放旧视图后的一轮完整 GC 能回收旧页；所有发布、失败写入和当前可变根删除仍保留原有失效逻辑。对象备份恢复重建所选写布局，图快照、WAL 和 Raft 网络格式不因范围分页改变。

## OrbStack 验证与基准

已覆盖条数及字节拆分、超大单条、增量实体及正反向边重写、冷缓存深分页、批量点读、跨页扫描、不同桶之间的端点和关系变化、自环、首部空页删除、整桶清空和重插入、legacy 候选桶冲突、缺页、页写入失败、CAS 失败、先发布后报错、取消释放、旧读视图与 GC、迁移、备份和恢复。全量 unit/vet/race 及开启范围页的 direct/WAL、重启恢复门禁已运行；最终提交的 GitHub CI 和发行门禁单独记录。

`BenchmarkIncrementalRangeDataAndDirectoryIO` 在 OrbStack Linux ARM64 上运行，每个规模冷/热缓存各三次。被修改桶均固定为 1024 条，相同字段宽度；只测数据页与平面目录的构建和文件 I/O，不含图变更、二级索引、writer fence 或 Raft 提交。

| ---: | ---: | ---: | ---: | ---: |
| 10,000 | 1024 条 / 25,497 B | 25,012 B | 1 / 0 | 47.1 / 23.5 ms |
| 100,000 | 1024 条 / 25,497 B | 36,089 B | 1 / 0 | 31.3 / 13.7 ms |
| 1,000,000 | 1024 条 / 25,497 B | 180,124 B | 1 / 0 | 35.8 / 19.5 ms |

每次隔离操作写一个数据对象和一个目录对象。10,000 条冷缓存样本的 `strace` 观察到 7 次 fsync，包含首次创建新版本目录的屏障。它不是完整 commit 或多副本 fsync 数量。

三次基准的累计进程 CPU 为用户态 65.76 秒、内核态 1.06 秒，峰值 RSS 约 4.42 GiB，均包含百万实体图及完整初始索引的准备，不能当作单次更新的 CPU 或峰值内存。隔离操作累计分配量约为冷缓存 49–57.5 MiB、热缓存 27–35 MiB。目录开销随页数增长仍然存在；本轮不宣称整个 commit 为恒定成本。

后台低占用页合并暂未启用。需要目录树或 pack 的进一步优化时，单独测量和设计，不改变本轮的有界页契约。
