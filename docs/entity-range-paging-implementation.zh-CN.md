# 实体与边范围分页：实现与启用

范围页用于消除实体、正向边、反向边的整桶增量重写。外层保留 64 个逻辑桶；桶内按原始 ID 字节顺序排列不可变物理页。每页最多 1024 条逻辑记录，Parquet 文件以 8 MiB 为目标上限；超限继续拆分，单条超大记录独立成页。

## 启用与兼容边界

`GRAPHDB_INDEX_RANGE_PAGES` 默认 `false`。新程序始终能读取两种目录，只有显式配置 `true` 才写范围页。三个 Compose 示例也接受该变量。

1. 保持开关关闭，升级所有读节点、写节点和 Raft 副本。
2. 确认相关节点均支持范围页后，统一开启该变量。
3. 对已有大租户重建索引。已明确标记为当前 64 桶的旧单页可按触及桶迁移；legacy 256 桶或归属不明确的目录通过完整重建迁移，避免向两个候选桶重复写入。

旧二进制不能安全分页范围目录。互操作实测曾让旧程序仅枚举出 2050 条中的 762 条，因此不能依赖旧程序自动回退，也不能把 `LayoutVersion` 当成能力协商。

需要恢复旧索引布局时，先停止新格式写入，用新程序关闭该变量并逐租户重建，再校验实体、边、反向邻接和索引健康。新程序、v2.3.8 源码编译的存储探针、再次启动的新程序已验证这一索引转换流程，包括旧程序的 GC 和读写。本验证只覆盖索引与图对象；WAL、Raft 数据目录及运行态快照仍须满足其各自的版本兼容要求，不能据此直接降级整个数据目录。

## 存储与读取契约

`EntityPageSpec` 和 `EdgeShard` 仍代表逻辑桶。父级 codec 标识范围布局；已有对象引用的版本化 `Role` 保存下界、排他上界和文件字节数，引用中同时保存 key、条数、内容 hash、schema hash 和物理 codec。这些字段进入已有目录序列化与目录 hash，不增加 Parquet 目录列。

路由目录 hash 覆盖有序范围、对象引用和校验信息；数据 hash 独立于路由边界。删除空页时扩大相邻范围可以只更新目录，继续引用原对象。范围页一页一个文件，不与其他页重新打包。旧 pack 保留读取支持，关闭开关时仍使用旧写布局及其原有 pack 限制。

增量更新按触及物理页归组，每页读取一次。只有发生变化的页重新编码；溢出页均衡拆分。`EntityRecord` 保持可选，分裂不更新未变化实体的定位提示。发布前沿用已有图版本、租户 generation、writer fence 和目录 CAS 检查；新页先持久化，目录整体发布。失败或取消保留原目录，发布结果不确定时保留可能已被引用的对象。

点读二分定位物理页，批量点读按物理页分组。实体和边扫描、正反向邻边分页从游标对应页开始，收集够结果即停止。邻边在关系类型之间惰性归并，每个迭代器只保留当前页；同桶稀疏候选仍可能访问多个页，其过滤工作计入查询成本并响应取消。查询路径不会先拼接整个桶。

目录编译缓存按租户、版本和目录 hash 隔离，限制为 512 项及估算 64 MiB；物理页复用现有按字节限制的缓存。缺页、内容不符或无效范围返回不可用或错误，不视为空结果。旧读视图与 GC 的并行保护沿用本地文件 epoch。删除历史索引／分片快照目录不再误报为根发布，使释放旧视图后的一轮完整 GC 能回收旧页；所有发布、失败写入和当前可变根删除仍保留原有失效逻辑。对象备份恢复重建所选写布局，图快照、WAL 和 Raft 网络格式不因范围分页改变。

## OrbStack 验证与基准

已覆盖条数及字节拆分、超大单条、增量实体及正反向边重写、冷缓存深分页、批量点读、跨页扫描、不同桶之间的端点和关系变化、自环、首部空页删除、整桶清空和重插入、legacy 候选桶冲突、缺页、页写入失败、CAS 失败、先发布后报错、取消释放、旧读视图与 GC、迁移、备份和恢复。全量 unit/vet/race 及开启范围页的 direct/WAL、重启恢复门禁已运行；最终提交的 GitHub CI 和发行门禁单独记录。

`BenchmarkIncrementalRangeDataAndDirectoryIO` 在 OrbStack Linux ARM64 上运行，每个规模冷/热缓存各三次。被修改桶均固定为 1024 条，相同字段宽度；只测数据页与平面目录的构建和文件 I/O，不含图变更、二级索引、writer fence 或 Raft 提交。

| ---: | ---: | ---: | ---: | ---: |

每次隔离操作写一个数据对象和一个目录对象。10,000 条冷缓存样本的 `strace` 观察到 7 次 fsync，包含首次创建新版本目录的屏障。它不是完整 commit 或多副本 fsync 数量。

三次基准的累计进程 CPU 为用户态 65.76 秒、内核态 1.06 秒，峰值 RSS 约 4.42 GiB，均包含百万实体图及完整初始索引的准备，不能当作单次更新的 CPU 或峰值内存。隔离操作累计分配量约为冷缓存 49–57.5 MiB、热缓存 27–35 MiB。目录开销随页数增长仍然存在；本轮不宣称整个 commit 为恒定成本。

上述基准来自 v2.3.10，未包含下面新增的邻接树与小页合并，不能作为新增实现的测量结果。

## 邻接 ID 树与局部合并

本节描述 v2.3.10 之后的当前源码能力，未包含在 v2.3.10 已发布资产中。

`GRAPHDB_INDEX_ADJACENCY_PAGES` 是独立的写开关，默认 `false`，要求同时开启范围页。先升级所有读者、写者、GC 节点和 Raft 副本，再统一开启并显式重建已有租户索引。业务写入不会为了缺失的邻接根转换整桶；无根桶仍走原路径。已有完整根的桶继续增量维护，关闭开关后须显式重建才移除根。三个 Compose 示例均接受该变量。

正反向完整边数据仍按 `edge.ID` 排列。每个逻辑桶额外保存一棵 `(endpoint, edge.ID)` 有序不可变树；正向 endpoint 为 From，反向为 To。叶子只有两个 ID，不含完整边或物理页位置；边页拆分、合并不改写邻接 ID。元组字段分别比较，JSON codec 明确版本，ID 内含分隔符也不产生歧义。对象引用相对存储 prefix，同租户迁移不会改变子节点 hash。

叶页最多 1024 项、实际 JSON 编码目标 256 KiB；内部节点最多 128 个子引用、目标 64 KiB。单个超大元组可独占叶页；内部节点为保持进展允许最多两个超大引用超过字节目标。单次变更复制受影响叶页和祖先路径；批量变更按叶归组。只有字段变化、ID/端点/类型不变时复用原根，不写邻接对象。全量构建在既有维护预算内按有界边页喂入树，不建整桶端点 postings map。

邻接遍历从 endpoint 与起始 ID seek，父栈前进，不维护会级联改写的 sibling 指针；按 ID 惰性读取当前完整边页。若树高为 h、访问 Q 个邻接叶页、检查 c 个邻接项，数据页读取 D 不超过 `min(P,c)`，其中 P 为该桶数据页数。完全同端点的密集桶验证根后直接走原 ID 流。关系过滤、自环的两个方向、取消和候选查询成本保留。节点 LRU 限制为最多 256 项／16 MiB；配置缓存时从原字段缓存份额划分，仍受条目与字节上限约束。

可选根通过新目录行种类序列化并进入目录 hash；无根目录的旧 hash 算法和物理 codec 不变。完整边页内容 hash 不包含根。`ListEdges` 继续按 `(关系类型, From 逻辑桶, edge.ID)` 扫描，游标格式、After、查询绑定、版本及 generation 不变。有效旧游标继续读取原 hash 对应快照；已回收的快照报错，不跳转到最新目录。旧二进制不支持带根目录，降级前用新程序关闭邻接开关并重建；需要更老布局时同时关闭范围页再重建。本说明不承诺新游标可由旧程序接续，也不承诺 WAL／Raft 目录降级。

实体、正反向边页在删除或内容缩小时尝试合并：低于 384 条或四分之一字节目标触发，只试一个相邻页；合并后不超过 768 条和实际编码 6 MiB。拆分后不立即合并，成功后不串联合并；单机编码名额繁忙时跳过可选合并。复制应用在原期限内等待编码名额，避免各副本因本地占用不同生成不同目录 hash。邻接叶页使用同样的 384／768 条滞回和 64／192 KiB 字节阈值，内部节点只沿受影响路径局部收缩。空桶删除引用，单条超大记录不反复尝试不可能的合并。

启用邻接写入的本地单机还会调度低优先级小页扫描。进程全局只有一个合并 worker，每片最多一对页，逐片重新读取目录、检查 manifest/fence 并 CAS 发布。统计对象读取和写入字节（包括目录与原子临时文件写入），以片间冷却限制平均总 I/O 为 16 MiB/s；一个有界片允许短时突发。冷却和冲突退避前释放视图、维护内存及构建名额；连续三次 CAS 冲突或其他错误停止，单次扫描最多五分钟。忙时调度可跳过，后续写入或显式重建继续整理。Raft 副本不会各自启动非复制的目录发布，其前台合并随原复制路径进行，显式维护通过既有维护流程执行。

GC 递归标记当前、反向及仍保留的历史目录根；损坏输入使收集停止，旧视图保护仍生效。构建中间节点和发布结果未知的对象不立即删除，进入后续 GC epoch。备份／新目录恢复重建所选布局。新根缺失、损坏或与数据页不符时返回错误，不当作空邻接，也不在部分输出后切换扫描路径。

当前完整数据页的平面目录仍随页数增长，目录加载、编译和发布不是 O(1)。节点构建、目录和后台写入成本应与完整边页写入分开统计。

## 范围读取、预取与取消

后续源码将范围目录的解码边界保留在不可变内存引用中，并计入现有目录编译缓存的字节预算。二分路由直接比较已解码的下界；修改对象 Role 后不会复用旧边界。磁盘格式、目录 hash、数据页 ID 顺序及旧 `ListEdges` 游标均保持原契约。首次目录编译仍随页数增长。

实体范围扫描和索引实体访问复用既有 Parquet 候选列与 Kind／Source 行组裁剪；已解码的页直接复用。范围 `ListEdges` 按 From／Source 的行组统计裁剪，Source 同时检查主来源、存在性来源和 provenance 来源，统计缺失或不能排除时保守读取。被裁剪的实体访问仍计入原有逻辑扫描预算；续页的首个部分范围读取候选 ID 列精确计费，不再重算 afterID 之前的行，也不因此解码字段 payload。对象存储上的裁剪减少解码，不代表无需下载整个物理对象。

实体和边的范围扫描最多向前预取一个物理页，共享现有全局 16 个预取名额；本地独占文件读取不启动网络预取。预取同时检查原始字节缓存和解码页缓存，后者命中时不因原始字节被淘汰而重新 GET；实际使用时仍按原策略检查缓存有效性。超出普通页大小或缓存字节预算的对象不预取。提前满足分页、请求取消或失败时，取消并等待本扫描的预取退出，释放名额；预取失败仍由实际读取确认错误，不把失败页当成空结果。本次只改变读取端，不新增持久化对象或改变页拆分、合并和写入策略。

反向目录的不可变缓存副本共享一次性的编译指纹，新的查询 lookup 不再反复对整份目录计算 SHA-256；目录更新或 TTL 重新加载时使用新的指纹状态。旧单页布局同样受益，编译后的目录仍受原有项数与字节预算限制。

共享图冷加载被已持久化的新图取代后，快照 reader 即使返回“连接已关闭”等非标准取消错误，等待者也会重新检查缓存。读取代次递增、同租户各缓存的发布／失效，与失败加载的最终判定通过同一个租户锁排序，避免多缓存发布中途泄漏旧读取错误；该锁不覆盖对象 I/O。只有最低版本满足、仍有效且发布后读视图代次未再次失效的替代项才能消化此类旧读取错误；替代项不存在或已失效时仍返回存储错误。先释放加载名额和 ReadView 再唤醒等待者，调用方自己的取消与期限继续生效。

后续审查将同一发布判定扩展到元数据读取、读取名额排队和显式／后台 `Refresh`。这些同步阶段也登记取消函数，发布满足最低版本的驻留图后可以中止旧工作；实际加载结束时先释放名额与读视图，再唤醒等待者。没有有效替代图、替代项已失效或版本不足时仍保留真实存储错误。同步阶段发起者的 context 取消／期限错误，不再传给其他仍有效的等待者；等待者重新申请加载，已准入的异步冷加载仍独立于首个调用方。热缓存读取在进入回调前检查已取消的请求，读取与缓存容量预算、TTL、布局和游标契约不变。
