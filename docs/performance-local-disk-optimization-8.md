# 本地磁盘性能优化，第八轮

日期：2026-09-18。工作区 `GraphDB-local-disk-v2`，分支 `codex/local-disk-v2`。

## 结论

减少实体分页与投影的深复制，移除扫描分页的重复过滤，并修复冲突记录嵌套值的读取隔离缺陷。宽实体投影基准的分配字节减少 **88.7%**，深分页减少 **97.5%**；扫描分页分配字节减少 **29.5%**。

这些收益针对具体读取路径。最终 HTTP 混合吞吐下降 1.9%，部分 WAL 尾延迟、compact 和启动/预热内存高水位仍有不利结果，**本轮不宣称整体加速，也不认定整体性能验收通过**。

## 实现与正确性边界

修改四个生产文件：

- `internal/query/match.go`：字段索引和索引范围查询在排序、聚合及分页确定后，只复制当前返回页。指定投影时，先选择返回字段，再深复制。字符串、数字等常见不可变值直接复用；投影中的嵌套对象重新绑定到独立副本。
- `internal/query/query.go`：复用分页后的响应组装逻辑，保持游标、版本、统计和聚合输出一致。
- `internal/storage/cache_scan.go`：缓存读视图已完成排序、游标定位和过滤，直接生成分页结果，省去第二次过滤、分片哈希计算和中间实体切片；保留结果深复制。
- `internal/graph/copy.go`：对冲突记录的 `ExistingValue`、`IncomingValue` 进行深复制。

已复现的隔离缺陷发生在同进程图模型读取/克隆接口：返回实体的冲突记录仅复制了结构体，嵌套 map/slice 仍指向原图。修改副本中的冲突详情会改变原图。扩展已有 `TestGraphCopiesDoNotShareNestedFieldValues` 后，旧实现失败；修复后的读取与克隆检查通过。原失败证据保留在 `conflict-before.log`。

在已有查询所有权测试中，覆盖索引等值/范围查询、完整实体/投影、连续分页、聚合计数，以及修改投影中的嵌套字段、labels、identity 后原图保持不变。扫描继续使用已有并发分页、过滤、取消、同版本恢复和缓存容量回退测试。

## 测量方法

OrbStack Linux arm64，Go 1.25.14，4 CPU / 6 GiB，独立 Linux 本地卷。before 是本轮开始的完整工作区，包含第七轮实现；after 是本轮最终实现。工具中的 `main-local` / `graphdb-main` 表示 before，**不是 Git main**。

上一轮分配采样中的实体复制、投影和扫描调用链仍存在于本轮起点，本轮通过独立基准重新测量。两版使用相同基准代码；新增基准文件内容也复制到 before 测试目录，before 的生产代码保持原样。

短预采样后，将微基准延长为每项 `-benchtime=1s -count=1`，以减少几十毫秒采样的波动。微基准只运行一组最终 before → after，不作为统计显著性的证明。原始短样本和中间版结果完整保留。

实际 HTTP 对照为最终版本一组 before → after；中间版也有一组对照。测试 gate 与性能对照错开。未清除 OS 页缓存，未停止其他 OrbStack 工作负载。

## 定点性能

| 场景 | before 耗时 | after 耗时 | before B/op | after B/op |
| --- | ---: | ---: | ---: | ---: |
| 10K 窄实体索引排序，返回 20 项 | 394.914 µs | 342.695 µs | 87,818 | 86,327 |
| 1K 宽实体投影，首页 20 项 | 692.904 µs | 184.098 µs | 971,868 | 110,118 |
| 1K 宽实体投影，跳过 500 项后返回 20 项 | 8,322.419 µs | 539.663 µs | 22,837,240 | 562,810 |
| 10K 实体缓存扫描，返回 100 项 | 28.063 µs | 17.145 µs | 92,539 | 65,267 |

宽实体包含一个保留的嵌套字段及 64 个不返回的嵌套字段，通过真实查询入口执行排序和投影；深分页使用上一页返回的游标。对应耗时下降约 73.4% / 93.5%，分配次数由 6,927 / 142,950 降为 1,456 / 1,974。

窄实体基准的分配次数由 382 降为 375，扫描由 218 降为 217。主要确定性收益是避免复制不返回的数据；不同字段宽度和分页深度的收益不能互相外推。

## 最终 HTTP 混合负载

相同种子目录，10,002 实体 / 5,001 边；WAL sync、flush 100 ms，4 个写入客户端 / 16 个查询客户端。每个写入客户端间隔 2 秒，每批 20 项。预热 5 秒、测量 60 秒。两版各发布 120 批、版本增加 120，全部请求成功；各完成 2 次后台 compact、1 次 GC。

| 指标 | before | after |
| --- | ---: | ---: |
| 混合吞吐 | 2,957.34 ops/s | 2,901.27 ops/s |
| 服务进程 CPU 用时 | 83.85 s | 85.97 s |
| 每个混合操作 CPU 用时 | 472.53 µs | 493.83 µs |
| 测量窗口采样峰值 RSS | 589,225,984 B | 577,511,424 B |
| 进程生命周期 RSS 高水位 | 1,195,409,408 B | 1,364,967,424 B |
| 峰值文件句柄 | 34 | 34 |
| 磁盘读取量 | 4,157,440 B | 29,794,304 B |
| 磁盘写入量 | 413,188,096 B | 411,373,568 B |
| 文件及目录同步次数 / 失败 | 4,748 / 0 | 4,751 / 0 |
| 同步累计耗时 | 7.027 s | 7.098 s |

吞吐下降 1.9%，CPU/操作增加 4.5%。窗口 RSS 下降 2.0%，但生命周期高水位增加 14.2%。采样记录确认，两版的高水位均在测量开始前已经出现，测量窗口内没有继续增长；它包含启动及预热，不能当作稳定查询内存，也不能据此认定峰值 RSS 门槛通过。磁盘读量受未控制的页缓存影响，保留实测值，不推断其全部变化由实现造成。

客户端延迟，单位 ms，顺序为 p50 / p95 / p99：

| 请求 | before | after |
| --- | ---: | ---: |
| 写入完成 | 177.496 / 191.665 / 195.036 | 175.178 / 198.641 / 205.470 |
| match | 4.452 / 12.796 / 17.794 | 4.593 / 12.931 / 18.193 |
| min_version | 4.186 / 12.392 / 17.511 | 4.279 / 12.526 / 17.742 |
| traverse | 2.181 / 9.202 / 13.578 | 2.274 / 9.501 / 13.897 |
| scan | 7.071 / 17.471 / 23.878 | 7.150 / 17.486 / 23.518 |
| WAL accept | 13.127 / 22.649 / 27.467 | 15.389 / 24.034 / 26.564 |
| WAL readable | 163.373 / 179.322 / 181.721 | 160.557 / 186.244 / 193.864 |

WAL accept p95 增加 6.1%，readable p99 增加 6.7%，写入完成 p99 增加 5.3%。readable 包含客户端 10 ms 状态轮询和可读性查询，每版仅 120 个写批样本；当前证据不足以可靠区分调度、GC、同步 I/O 波动和改动影响。保留不利结果，WAL 尾延迟的“不回退超过 5%”验收仍未定。

### 维护、恢复与重启

| 操作 | before | after |
| --- | ---: | ---: |
| export | 81.05 ms | 74.44 ms |
| compact | 628.47 ms | 742.20 ms |
| 本地快照备份 | 531.82 ms | 532.84 ms |
| 覆盖恢复 | 4,539.83 ms | 4,369.44 ms |
| 维护 CPU 用时 | 8.65 s | 8.56 s |
| 维护采样峰值 RSS | 659,968,000 B | 719,966,208 B |
| 维护同步次数 / 失败 | 756 / 0 | 756 / 0 |

每版覆盖恢复及重启后的完整导出均与本版备份前相同。compact 单次耗时增加 18.1%，尚未确立原因或稳定性，不能列为已通过的性能路径。单次进程重启查询为 39.87 → 54.66 ms；每版仅一个样本，且 OS 页缓存未控制，不作为冷读 p95。

中间版的混合吞吐为 2,992.23 → 2,912.64 ops/s，也没有总体收益。最终版减少了标量值重新绑定造成的额外分配；这项改动有微基准依据，仍未改善本次 HTTP 混合吞吐结论。中间版不利结果、源码摘要及短预采样保留在 `intermediate/`，未择优替换最终数据。

## 正确性验证

- 全量 `go test ./...`：12 个包、1,306 个顶层测试通过；`go vet ./...` 通过。
- race：完整 graph 136 项、完整 query 141 项、存储边界 208 项、完整 HTTP API 184 项顶层测试通过。
- 实际 HTTP release gate：direct/WAL 并发写入查询、图查询、分页、来源治理、租户隔离、索引更新、scan/export、compact、备份恢复及重启通过。Python SDK 12 项通过；Go SDK 包包含在全量测试中。
- 独立 MinIO gate：multipart 发布、禁止 manifest 重定向、重新打开后的校验恢复在 race 下通过；HTTP 对象存储备份、全新目录发现及 dry-run、恢复、覆盖恢复、恢复演练和重启校验通过。补齐单元/race 阶段因无外部 S3 配置而跳过的测试。
- 当前实现和回归测试的哈希与最终验证源码一致；`git diff --check` 通过。本轮创建的测试容器和 MinIO 网络已清理。

最终验证没有发现其他重大正确性回归。本轮未运行 30 分钟持续负载、100K HTTP 容量比较、受控 OS 冷缓存或完整历史 release 兼容矩阵。
