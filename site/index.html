A graph core shaped for production.

Flexible entity modeling meets bounded queries, explicit freshness, and the controls needed to run the database.

Storage

Durable data without a storage cluster.

Persist Parquet snapshots, commits, manifests, and indexes on local disk. Keep recovery snapshots in optional S3-compatible storage.

Query

Bound every graph walk.

Match, traverse, inspect impact, and find shortest paths with explicit limits.

match pattern neighbors traverse impact shortest_path
Freshness

Make read visibility explicit.

Carry a committed version into the next query when a workflow must observe its own write.

min_version: committed_version

Update and query in one process.

Each process owns its local directory. Choose standalone or independent Raft replicas; concurrent reads see committed versions while updates continue.

Recovery boundary Standalone or optional Raft

Opt in to scheduled snapshots, retries, retention, and restore drills. For high availability, the same binary also supports independent Raft replicas and tenant-sharded groups. Cross-host and production capacity acceptance remain pending.
